# Поиск дел по темам и ключевым словам — исправление 18.10.2026

## Проблема
Раньше поиск в \`moscow-cases-explorer.tsx\` сравнивал строку только с \`subject\` и \`number\` уже внесённых дел. Поэтому запрос «увольнение» оставлял все категории, но давал 0 результатов и не позволял найти даже раздел «Трудовые споры».

## Исправлено
1. Поиск идёт по **названиям, описаниям категорий, правовым нормам, набору безопасных юридических словоформ/синонимов**, а также по номерам, предметам и известным результатам размещённых дел.
2. Пока пользователь печатает, показываются **только подходящие категории**. Они получают заметную рамку и метку «Подходящая тема», раскрываются автоматически, а точная фраза подсвечивается в текстах при совпадении.
3. Примеры запросов: «увольнение», «зарплата», «алименты», «мошенничество», «ДТП», «кредит», «02-5195/2026».
4. Отдельные счётчики категорий и непосредственно **совпадающих дел**, потому что распознавание темы не означает наличие конкретного решения.
5. Если категория подходящая, а совпадающих дел в ограниченной базе нет, показывается явное сообщение; другие дела этой категории доступны через отдельный раскрывающийся блок с надписью «не совпадают с запросом».
6. Кнопки популярных тем и очистка строки, результаты доступны с клавиатуры и через \`aria-live\`, мобильная раскладка.
7. Поиск локальный: не выполняет запросов к внешнему сайту при вводе. Документ открывается только если проверен и опубликован по правилам проекта, количество дел не увеличено искусственно.

## Границы
Это не полнотекстовый поиск по PDF и не все дела суда. До проверки и загрузки полных актов нельзя утверждать, что локальная база содержит все решения по «увольнению». Переход на официальный реестр остаётся для расширенного поиска. Никаких фиктивных дел не создано.

## Проверка
Node тест \`apps/web/tests/moscow-case-search.test.cjs\` проверяет настоящий TypeScript helper; отдельно фиксирует сценарий скриншота «увольнение», поиск точного дела, другие темы и отличие попадания в категорию от попадания в конкретную карточку. Команда включена в GitHub Actions перед сборкой. Python-проверка контролирует форму и сохранение десяти предыдущих карточек.
