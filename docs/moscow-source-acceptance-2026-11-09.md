# Московские суды: консервативная автоматическая сверка фактов

Дата: 09.11.2026. `importer/moscow_source_acceptance.py` — **закрытый
диагностический модуль**, не публикационный импортёр.

Условия автоматической технической сверки **одного факта**:
- существует не менее двух официальных документов/снимков с разными
  `issuer` и URL, проверенными датами и SHA-256;
- оба подтверждают одно и то же нормализованное значение;
- нет иных **официальных** противоречащих значений;
- поле относится к разрешённым несекретным реквизитам.

Если два официальных документа расходятся, статус
`conflicting_official_sources_hold`. Система НЕ выбирает произвольно
из противоречащих официальных источников. Отличающийся неофициальный
источник с одним официальным вызывает статус
`official_preferred_nonofficial_conflict_review`, но автоматическая
публикация всё равно отключена.

Один официальный источник — **не** двойная независимая юридическая
проверка. URL в официальном домене без содержимого и контрольной суммы
сам по себе не удостоверяет факт. Статус согласованности метаданных не
равен юридической проверке текущих полномочий судьи и текста акта.

Пример запуска на закрытом JSON-манифесте:
```bash
python3 importer/moscow_source_acceptance.py --input /srv/sudy-private/evidence/claims.json
```

Скрипт выдаёт только агрегированные статусы и идентификаторы суда/
поля; не печатает значения, ФИО участников и тексты источников.
Формат каждой записи:
`courtSlug, field, value, sourceUrl, sourceKind, issuer,
sourcePublishedOn, capturedOn, snapshotSha256`.

Никакого чтения неразрешённых судебных сведений, отправки в Git,
автоматической публикации и Deploy.
