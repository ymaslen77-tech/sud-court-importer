# Получение реальной московской выгрузки: проверяемый приём без догадок

Статус: **OFFLINE READY / LIVE DOWNLOAD BLOCKED**. Технический импорт
реализован, но официальные условия автоматического обращения, точный живой
export URL и схема полного актуального JSON **пока не подтверждены**.
Нельзя отмечать федеральное/московское покрытие как завершённое.

## Что обнаружено в доступных источниках

1. Официальный реестр https://data.mos-gorsud.ru/opendata показывает категорию
   «Контакты и часы приёма» (1 набор). Это ещё не идентификатор конкретной выгрузки.
2. Неофициальный **исторический** каталог
   https://data.apicrafter.ru/packages/mosgorsud-contactsandhoursgfjvi
   содержит запись о контактах и часах приёма на **26.10.2021** (36 записей),
   а также предполагаемый ID `1577117189318-contactsandhoursgfjvi`.
   Он **не является доказательством** текущей схемы, действующего URL
   или прав использования в октябре 2026 года.
3. На https://data.mos-gorsud.ru/terms-of-use находится страница условий.
   Её содержимое пока не удалось достоверно получить для автоматической
   оценки: нельзя подменять это предположением, что автоматический сбор разрешён.
4. Настоящие отдельные контакты можно сверять с официальными
   https://www.mos-gorsud.ru/courts и страницами отдельных судов,
   но такие страницы не образуют подтверждённую лицензию на массовый обход.

## Проверяемая последовательность оператора

1. В браузере открыть конкретный набор «Контакты и часы приёма» на **официальном**
   портале, проверить точный URL, дату последнего изменения, формат JSON
   и условия использования. Зафиксировать эти реквизиты в протоколе источника.
   При отсутствии разрешённого канала не запускать сетевой планировщик.
2. Получить файл разрешённым способом и сохранить **оригинал без изменений**
   в `data/import/moscow-raw-YYYY-MM-DD.json`, вне Git. Не присваивать
   историческому архиву дату новой выгрузки.
3. Выполнить исследование полей (не показывает значения записей):

   ```powershell
   docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/moscow_raw_export.py inspect /input/moscow-raw-YYYY-MM-DD.json
   ```

   Вывод фиксирует количество записей, ключи/типы, SHA-256 оригинала,
   `source_rights_verified=false`, `currentness_verified=false`.
4. После ручного исследования фактического файла создать
   `data/import/moscow-map.json`, сопоставив **существующие** исходные ключи:

   ```json
   {
     "fields": {
       "courtCode": "REAL_RAW_CODE_KEY",
       "courtName": "REAL_RAW_NAME_KEY",
       "courtAddress": "REAL_RAW_ADDRESS_KEY",
       "courtSiteUrl": "REAL_RAW_OFFICIAL_COURT_PAGE_KEY",
       "courtTelephone": "REAL_RAW_PHONE_KEY",
       "courtWorkHours": "REAL_RAW_HOURS_KEY"
     }
   }
   ```

   Пример имён `REAL_RAW_*` — **заглушка для объяснения формата**, не
   описание настоящего экспорта. Поля `courtCode`, `courtName`,
   `courtAddress`, `courtSiteUrl` обязательны. Если в исходном файле
   нет проверенных кодов или URL суда, **не генерировать** их из
   названий/случайных чисел: отклонить файл и выполнить отдельную
   доказательную сверку с другим официальным реестром.

5. Создать каталог выходных файлов `data/import/normalized` (в PowerShell:
   `New-Item -ItemType Directory -Force data/import/normalized`).
   Исходный `/input` монтируется read-only, отдельно `/output` — writable.
   Проверить контрольную сумму оригинала и явно подтвердить ручное
   сопоставление схемы; создать новый нормализованный файл:

   ```powershell
   # Сначала возьмите raw_sha256 из результата inspect
   docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/moscow_raw_export.py normalize /input/moscow-raw-YYYY-MM-DD.json --mapping /input/moscow-map.json --expected-sha256 ACTUAL_64_HEX_SHA256 --attest-schema-reviewed --output /output/moscow-normalized-YYYY-MM-DD.json
   ```

   Нормализатор проверяет JSON, коды судов, уникальность записей,
   допустимость официальных URL и вложенных дополнительных полей.
   Отчёт **не утверждает** юридическую актуальность или права
   повторного использования. Выходной файл не перезаписывается.
6. Отдельно выполнить `moscow_sync.py validate /input/normalized/moscow-normalized-YYYY-MM-DD.json`, затем проверить каждую
   запись по официальной веб-странице и правила использования источника.
   Только после этого формировать inbox manifest с действительным
   `dataset_url`, фактической датой `captured_on` и честной
   отметкой `reuse_rights_confirmed`. Импорт через `inbox.py stage`
   создаст приватные кандидаты, но не публичные карточки. Для публикации
   действует отдельный `cli.py approve` с подтверждением актуальности.

## Запреты и критерии приёмки

- Никаких вымышленных судебных кодов, URL, дат скачивания, ФИО или телефонов.
- Архивы 2021 года не используются как подтверждение актуальности на 2026 год.
- Нельзя запускать live schedule только по наличию DOM-страницы набора.
- Публикация не происходит при `inspect`, `normalize`, `validate`,
  `inbox.py stage`, изменении контрольной суммы или повторном прогоне.
- Готовность настоящего источника подтверждается: **проверенные условия**,
  **действующий export URL**, **неизменённый исходный файл**, **хеш**,
  **верифицированная схема**, **статус каждого суда** и **CI**.

Сейчас автоматическое получение актуальных файлов и массовая публикация
официальных карточек не включены. Результат этого этапа — безопасная подготовка
и проверяемое нормализующее звено, а не самостоятельная выгрузка.
