# План приёмки общероссийского судебного справочника

Данный документ — измеримые критерии, а не утверждение о выполнении. Каждый этап должен иметь успешный CI, сохранённый журнал источников и реальные счётчики в PostgreSQL. `localhost` и тестовые фикстуры не доказывают заполнение публичной базы.

## Этап 1. Официальные источники и разрешения (блокирующий)

- [ ] Для каждой категории судов подтверждены издатель, официальный URL, способ получения данных, дата проверки, разрешённость повторного использования, ограничения автоматических запросов, допустимая частота.
- [ ] Подтверждено, что машинный формат *действительно* доступен, а не только присутствует кнопка «JSON» в интерфейсе.
- [ ] Для каждого потока хранятся исходный файл/контрольная сумма, дата получения, регион и журнал ошибок.
- [ ] Сетевой загрузчик включается только после проверки прав и robots/ограничений источника.

Приёмка: минимум один подлинный повторяемый поток, документированные ограничения и успешная загрузка двух последовательных выпусков без тестовых фальсификаций.

## Этап 2. Общероссийский реестр

- [ ] По всем субъектам РФ и категориям судебных органов собирается полный доказуемый реестр.
- [ ] Суд и судебный участок, присутствие и судейская должность не отождествляются.
- [ ] Объединение по классификационному коду допускается только при достоверной идентификации.
- [ ] Удаление записи из частичного снимка не считается закрытием суда.
- [ ] Массовая публикация — только после независимой редакционной проверки официальных адресов и кодов.

Приёмка: отчёт по регионам/типам с количеством **уникальных опубликованных** судов, долей подтверждения, пустыми регионами и источниками. Числа должны вычисляться из БД, а не задаваться вручную.

## Этап 3. Контакты и состав судей

- [ ] Подтверждены отдельно телефоны экспедиции, канцелярии, приёмной, часы работы, режим приёма и инструкции подачи.
- [ ] Назначения/освобождения судей подтверждены первоисточниками; однофамильцы не объединяются автоматически.
- [ ] Изменения отдельных полей проходят через очередь редакционной сверки с датой и ответственным.

Приёмка: контролируемые кейсы изменения телефона, перехода судьи и устаревания источника, включая отрицательные тесты.

## Этап 4. Редакционный кабинет

- [ ] Доступ закрыт по умолчанию; журнал всех решений и источников.
- [ ] Можно принять/отклонить конкретную карточку и предложение, но подтверждение HTML diff не публикует факты.
- [ ] Показаны ошибки, очереди, незакрытые и просроченные проверки, заполненность регионов.

Приёмка: авторизационные, интеграционные и audit-тесты.

## Этап 5. Карты, фасады и SEO

- [ ] Координаты проверены; карты только с атрибуцией и информированием о внешнем запросе.
- [ ] Фасад реально принадлежит суду; автор, лицензия, источник доказаны; EXIF удалён.
- [ ] Канонические адреса, уникальные H1/title, structured data, sitemap и noindex для пустых/устаревших карточек.
- [ ] Не публикуются искусственные рейтинги, неподтверждённые фото и шаблонные «тонкие» страницы.

Приёмка: аудит выборки реальных карточек и проверка индексационных директив.

## Этап 6. Круглосуточный мониторинг

- [ ] Постоянно доступный production-хост, защищённые секреты, резервные копии и восстановление.
- [ ] Фоновые задания имеют retry, ограничение запросов, блокировку параллельных запусков и алерты об ошибках.
- [ ] Контакты и назначения контролируются независимо; проверяются обе очереди новых и неразобранных обновлений.
- [ ] При выключенном компьютере разработчика сервис **не останавливается**.

Приёмка: многодневные успешные проверки, демонстрация алерта и восстановления после сбоя.

## Этап 7. Судебная практика

- [ ] Ссылки на решения и дела происходят с первоисточников, имеют суд, номер, дату, источник и статус.
- [ ] Учитываются ограничения персональных данных и опубликованных/обезличенных судебных актов.
- [ ] Связь с судьёй только при подтверждённой идентичности.

Приёмка: проверенные выборки, отсутствие фиктивных дел, корректная обработка совпадающих номеров.

## Этап 8. Запуск

- [ ] `importer/readiness.py --fail-if-not-ready` проходит с production HTTPS origin.
- [ ] Проверены реальные домен, SSL, доступность извне, мониторинг, бэкапы и восстановление.
- [ ] Измерено фактическое покрытие справочника по видам судов и регионам.
- [ ] Черновой PR закрывается объединением только после осознанной итоговой acceptance-проверки.

## Фактическая текущая граница

Построены прототипы структур, валидаторы, ручной staging, diff/review и части кабинета. Но пока нет доказанной всеобщей разрешённой машиночитаемой выгрузки и массовой редакционно проверенной публичной базы. **Не отмечать этап завершённым только из-за зелёного CI.**
