# Структурированная модель зданий, контактов и подсудности (15.10.2026)

Миграция `db/migrations/013_court_linked_facts.sql` вводит три самостоятельные связанные таблицы для **уже заведённых** судов. Она не меняет `court_import_rows`, `court_discovery_rows` или публичную таблицу `courts` и не переносит старые текстовые поля автоматически.

| Таблица | Назначение | Обязательная проверка |
| --- | --- | --- |
| `court_buildings` | Основное/дополнительные здания, адреса, доступность | источник, проверяющий, дата и отдельное решение |
| `court_contact_points` | Телефоны, факсы и e-mail **конкретного подразделения**; опциональная связь со зданием | роль контакта и персональный официальный источник |
| `court_jurisdiction_units` | Территория, судебная инстанция, специальная компетенция; уровни гранулярности | юридическое основание, дата и редакционное подтверждение |

Все новые сущности по умолчанию `draft`; публичные запросы в будущих API должны выбирать **только** `review_status='approved'`. Одобрение невозможно без `reviewed_by` и `verified_at`, но это машинный барьер, не юридическое заключение. Один суд может иметь несколько зданий и разных подразделений. Единственный подтверждённый основной адрес защищён частичным уникальным индексом.

### Важные пределы

- Модель `court_jurisdiction_units` пока **не является точным поиском подсудности по улице и дому**. Значения `description` не должны использоваться для автоматического сопоставления адресов; в дальнейшем нужны нормализованные адресные единицы, точные исключения и контроль редактором. Регион размещения военного суда не обязан совпадать с префиксом классификационного кода.
- Наличие судебного дела или фамилии на официальном сайте не подтверждает текущую должность судьи; для этих сущностей остаются специальные уже существующие таблицы и отдельные правила допуска.
- Новые таблицы не содержат фактов о десяти пилотных судах: сначала индивидуальная проверка, затем ручное занесение подтверждённых значений.
- Миграция включена только в рабочий репозиторий; перед применением к Neon выполнить базовую/интеграционную приёмку и проверить резервное восстановление. Применение базы в production — самостоятельное действие.

Существующие разделы карточки, API и сайт не должны считать создание этих таблиц подтверждением наличия данных.
