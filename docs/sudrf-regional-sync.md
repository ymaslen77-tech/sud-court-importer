# ГАС «Правосудие»: региональные суды → staging → мониторинг изменений

## Источник, который фактически проверен

Официальная региональная выдача Новосибирской области (федеральные суды):

https://sudrf.ru/index.php?act=go_search&court_subj=54&id=300&searchtype=fs

Страница содержит имя суда, классификационный код, адрес, телефон, электронную почту и ссылку на официальный сайт. В этой выдаче реально встречаются коды RS (районные/городские), OS (суд субъекта), GV (гарнизонный военный), KV (кассационный военный), AJ (апелляционный суд общей юрисдикции). Другие префиксы нельзя допускать до проверки на официальном источнике.

Проверочный фрагмент на 4 реальных объекта хранится в importer/tests/fixtures/official_sudrf_novosibirsk_excerpt.txt и использован в unit/CI. Это **только часть** официальной выдачи, не полный список судов Новосибирской области и не подтверждённая на сегодняшнюю дату редакционная карточка.

## Как работает обработка

1. Сотрудник легальным способом получает видимую региональную выдачу и сохраняет как UTF-8 HTML или текст. Автоскачивание официальных сайтов из-за неизвестных правил доступа не включено; если доступ или формат страницы не соответствует требованиям — процесс останавливается.
2. importer/sudrf_listing.py проверяет точный регион, домен sudrf.ru, коды судов и обязательные поля. Если хотя бы один найденный элемент неполон, импорт отклоняется целиком.
3. CLI `sync` создаёт закрытый пакет import_rows, привязывает к нему SHA256 **исходного файла** и дату получения, находит предыдущий пакет с тем же официальным URL и создаёт судебные diff-требования.
4. Поля, появившиеся или изменённые между снимками, попадают в court_registry_diff_items. Отсутствовавшие записи по умолчанию **не считаются упразднёнными судами**: региональная страница могла быть загружена не полностью.
5. Редактор проверяет каждое изменение на первоисточнике, отдельно подтверждает конкретную карточку через cli.py approve или подаёт proposal для изменившегося поля в profile.py. Простое acknowledgement/ignore diff-события НЕ публикует новое значение.

Детали аудита: db/migrations/007_court_registry_diffs.sql, importer/registry_diff.py. Каждый diff run связан с двумя пакетами одного source URL и хранит статусы обработки/проверяющего.

## Команды на Windows в запущенном Docker Desktop

Примените миграции из корня актуальной ветки:

    powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\apply-import-migration.ps1

Поместите локальную копию официальной страницы в `data\import\54-listing.html` (если страница динамическая и в HTML нет записей, сохраните текст видимой региональной выдачи в UTF-8 .txt). Перед массовым сбором проверьте условия использования портала и robots, не обходите блокировки.

Для предварительной проверки **без записи в базу**:

    docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/sudrf_listing.py validate /input/54-listing.html --region 54 --region-name "Новосибирская область" --source-url 'https://sudrf.ru/index.php?act=go_search&court_subj=54&id=300&searchtype=fs'

Чтобы записать файл в закрытый staging и **автоматически сформировать очередь изменений** относительно предыдущего полного или частичного снимка:

    docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/sudrf_listing.py sync /input/54-listing.html --region 54 --region-name "Новосибирская область" --source-url 'https://sudrf.ru/index.php?act=go_search&court_subj=54&id=300&searchtype=fs' --captured-on 2026-10-13 --reviewer "Ответственный редактор" --attest-reuse-rights

Дату меняйте на **фактическую** дату получения снимка. Флаг подтверждения прав ставьте лишь после самостоятельной проверки условий конкретного источника.

Список предложенных изменений:

    docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/registry_diff.py pending --limit 100

Закрыть отдельное замечание ПОСЛЕ проверки:

    docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/registry_diff.py acknowledge --item-id 1 --reviewer "Ответственный редактор" --attest-reviewed

Если событие оказалось ложным, можно добавить `--ignore`, с сохранением аудита. Ни одна из этих команд не публикует данные автоматически.

## Предупреждения по качеству

- Сравнение неполных снимков полезно для выявления изменившихся сведений. Полноту региона оно не доказывает.
- Исчезновение суда из выгрузки не подтверждает его упразднение. Для отсутствующих нужны два полных набора, именная аттестация полноты и юридическая проверка.
- Внутренние коды судебных объектов могут изменяться или принадлежать разным реестрам — сопоставляйте коды и историю преобразований.
- Обнаружение смены телефона не гарантирует, что новый телефон верен; нужна проверка официального профиля суда, источника и актуальности.
- Назначения судей проверяются отдельно через документы о полномочиях и importer/judges.py, не выводятся автоматически из названия или телефона суда.
- Без постоянного хоста/допустимых сетевых источников это **полуавтоматическая offline pipeline**, не живой общероссийский мониторинг.
