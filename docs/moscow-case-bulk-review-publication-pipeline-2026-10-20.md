# Москва — массовое наполнение судебной практики (этап 23)

## Фактический статус
Двенадцать карточек судов уже доступны. На момент этого этапа **33** номера дел имеют ранее проверенные результаты, а **0** полнотекстовых судебных актов прошли приёмку и размещены на собственных страницах. Это не выполнение цели в 50 актов на каждую разрешённую категорию.

Официальный портал: https://data.mos-gorsud.ru/opendata. У него есть крупные JSON-выгрузки гражданских, административных и уголовных дел первой инстанции. Описание полей включает наименование суда, номер, категорию, состояние или результат, дату, сведения о судебных актах и персональную ссылку на дело. Прямое скачивание полного архива из ограниченного рабочего окружения не удалось; **ни одного массового импорта из этого источника пока не выполнено**.

## Исполняемый конвейер

1. Получить оригинальный JSON/NDJSON с официального портала и сохранить его **вне репозитория**, без размещения ФИО участников и других исходных персональных данных на публичном сайте. Отдельно проверить действующие условия использования.
2. Выполнить локальную подготовку (свыше 20 МБ требует установленного \`ijson\`):
   \`\`\`bash
   python -m pip install ijson
   python importer/stage_moscow_open_data.py --input /secure/official-cases.json --output /secure/research-candidates.json
   \`\`\`
   Ограничение выборки на суд и тему — 250 записей, общий лимит входных записей — 2,5 млн; данные участников не попадают в подготовленный файл. Каждая строка сохраняет \`source_record_hash\`, персональный официальный URL дела и статус \`research_only\`.
3. Сверить первоисточник по **каждому** номеру, предмет, итог и дату. Для допуска к публикации сформировать в защищённом окружении \`reviewed.json\` со структурой \`{"schema_version":1,"records":[...]}\`, где каждый элемент содержит \`court_slug\`, \`number\`, \`topic_id\`, \`safe_public_subject\`, \`verified_first_instance_outcome\`, \`decision_date\`, \`reviewed_on\`, \`reviewer\`, \`source_record_hash\`, \`official_docket_url\` и флаги \`official_docket_verified\`, \`first_instance_result_verified\`, \`privacy_reviewed\`, \`statutory_publication_checked\`, \`source_reuse_confirmed\`, \`editor_approved\`.
4. После реальной редакторской приёмки:
   \`\`\`bash
   python importer/publish_reviewed_moscow_cases.py --review /secure/reviewed.json
   \`\`\`
   Это создаёт/обновляет публичный \`apps/web/app/lib/moscow-reviewed-cases.json\` **только метаданными дел**, без PDF и без сведений об участниках. Повторный запуск не дублирует одинаковые записи. Внести результат в PR, выполнить CI и опубликовать после проверки.
5. В Next.js каталог объединяет прежние 33 подтверждённых результата и новые одобренные метаданные с контролем номера, категории, источника. Новые страницы дел открываются по динамическому маршруту: рост числа записей не приводит к статической генерации десятков тысяч HTML-страниц.
6. **Для каждого полного судебного акта** дополнительно нужны оригинальный бинарный файл, сверка источника/резолютивной части, проверка обезличивания и ограничений закона № 262-ФЗ, подтверждение SHA-256 и отдельное разрешение к публикации. Метаданные дела и ссылка на акт не засчитываются как размещённый акт.

## Технические ограничения и честная статистика

- 50 — целевое число **полных, проверенных** актов по каждой допустимой категории **для каждого суда**. Не следует объявлять его фактической цифрой. Отдельные категории и типы актов могут быть запрещены для публикации.
- Нельзя делать вывод о виновности по номеру обвинения; результат первой инстанции может измениться при обжаловании.
- Массовые исходные JSON и оригиналы решений не должны попадать в GitHub без редакционной очистки.
- Не настроены массовая проверка и обновление дел в реальном времени: для этого нужен разрешённый, документированный канал данных и отдельный процесс редакционной переоценки.
- Публичные страницы исследовательской московской серии сохраняют \`noindex\` до самостоятельной юридической и SEO-приёмки.

## Ожидаемая работа после получения исходников

Выгрузки по гражданским, КАС и уголовным делам поступают на вход отдельно. Первый приоритет — реальные трудовые, жилищные, потребительские и долговые дела, у которых документ официально опубликован. Затем — остальные разрешённые категории. Для каждого суд/категория строится отчёт о подтверждённых исходах, ссылках на акты, скачанных оригиналах и реально опубликованных проверенных документах.
