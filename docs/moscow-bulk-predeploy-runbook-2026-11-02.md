# Суды России — подготовка к самостоятельной массовой загрузке (02.11.2026)

**Ветка:** `infra/coolify-russian-vps`. **Приложение в Coolify:** `sudy-web`.  
**Статус:** код конвейера и его интеграция с судейским каталогом подготовлены. Фактические массивы публичного портала ещё НЕ загружались в VPS, НЕ сохранялись в GitHub и НЕ опубликованы.

## Официальные источники

- https://data.mos-gorsud.ru/opendata — реестр из 40 наборов.
- Апелляционные гражданские дела Московского городского суда: https://data.mos-gorsud.ru/opendata/1577117744056-casesgroupmgsappealcivilwtxga. Паспорт содержит УИД, нижестоящий суд, номер и судью первой инстанции, результат и ссылки на судебные акты.
- Уголовные дела первой инстанции: https://data.mos-gorsud.ru/opendata/1577116724824-casesgroupfirstcriminalluivn.
- Перед загрузкой требуется получить оригинальный официальный JSON гражданских дел первой инстанции (либо иной набор первой инстанции с точной картой полей). Фактический массив может иметь отличающуюся JSON-обёртку. Скрипт останавливается на незнакомой схеме вместо угадывания.

На просматривавшихся страницах наборы датированы июлем 2026 года. Данные НЕ являются актуальным на ноябрь 2026 реестром всех дел. Актуальность отдельных карточек нужно уточнять на `mos-gorsud.ru`.

**Условия повторного использования именно data.mos-gorsud.ru не удалось достоверно проверить через доступный текстовый интерфейс.** Перед запуском с `--ack-source-terms` необходимо открыть раздел «Условия использования» на самом портале и убедиться, что переработка метаданных с указанием источника допустима. Не переносить ФИО сторон, запрещённые тексты, документы с ограничением публикации.

Судейский каталог до массового импорта содержит 418 персональных записей разного уровня достоверности и 27 привязанных дел в небольшой подборке. Не путать количество записей с числом действующих судей. Для пяти судов пока нет полного проверенного кадрового состава.

### Как формируются уровни проверки

1. **`single_official_record_unchecked_live`** — один официальный набор данных, без проверки свежей индивидуальной карточки; выводится как реестровое сведение, НЕ как полноценная юридическая проверка.
2. **`official_registers_concordant`** — сведения первой инстанции и официального апелляционного набора совпали по УИД, делу и судье. Даже это НЕ подтверждает мотивы решения и исход апелляции.
3. **Проверенный полный акт** — отдельный документ с подтверждённым опубликованным текстом, хешем, приложенным законным основанием и проверкой обезличивания; не возникает автоматически при массовой загрузке.

Защита: дубли по суду/УИД/номеру, несовпадение УИД при одинаковом номере, неизвестный судья, неверный официальный домен, защищённые семейные/детские категории и неопределённые статусы судебного акта. Конфликтные записи не включаются в публичный файл. Это техническая фильтрация, а не гарантия качества каждой карточки.

## Как выполнить на VPS, когда файлы будут получены

Скачать два официальных файла через кнопку **«JSON»** соответствующего набора данных и поместить в закрытое расположение VPS, например:
- `/srv/sudy-private/moscow-first.json` — дела первой инстанции;
- `/srv/sudy-private/moscow-appeal.json` — гражданские апелляционные данные.

Оригиналы хранить вне веб-каталога, директории Git и общедоступных URL. Проверить размер, права и возможность читать файлы пользователем, выполняющим команду.

Перейти в локальный Git checkout проекта, где ветка `infra/coolify-russian-vps`. **Первая проверка без публикации**:

```bash
bash scripts/moscow-bulk-release.sh --first /srv/sudy-private/moscow-first.json --appeal /srv/sudy-private/moscow-appeal.json
```

Скрипт устанавливает `ijson` в закрытое виртуальное окружение, создаёт `data/import/moscow-stage.XXXXXXXX/prepared` и формирует `report.json`, `candidates.ndjson`, `appeal_links.ndjson`, `quarantine.ndjson`. Все эти файлы игнорируются Git.

Сначала изучить `report.json`: сколько распознано судов, отклонено записей, обнаружено противоречий, сколько связок с апелляцией, сколько кандидатов допущено. Если большинство записей отвергнуто из-за структуры, НЕ продолжать с `--apply`; сначала согласовать схему. Пустая или подозрительно малая выборка не считается успешно завершённым импортом.

**После проверки условий портала и отчёта** можно одной командой подготовить новую партию, записать только допустимые метаданные, сохранить резервную копию вне веб-приложения и отправить единственный JSON в GitHub:

```bash
bash scripts/moscow-bulk-release.sh --first /srv/sudy-private/moscow-first.json --appeal /srv/sudy-private/moscow-appeal.json --apply --ack-source-terms --push
```

Для более строгого режима — `--mode crosschecked`, тогда записи с одной первичной выгрузкой не переходят в публичную подборку. По умолчанию включён режим `official`, где одиночные официальные записи показываются с отдельной пометкой неопределённости. По умолчанию лимиты: **100 дел на суд, 25 на судью**, максимум 250/50. Массовая выгрузка может содержать намного больше строк: первый этап сознательно ограничивает размер JSON, входящего в Next.js.

**Важное ограничение:** `--push` требует настроенного GitHub-доступа на машине и чистой рабочей ветки; если доступа нет, изменения остаются только в локальном checkout. Команда не выполняет Deploy в Coolify и не пишет в Neon. Для появления нового JSON на сайте нужны GitHub CI **Success** и последующий **Redeploy приложения `sudy-web`** через Coolify.

После публикации проверить:
- `https://sud-russia.ru/courts/moscow/judges`;
- персональную страницу выбранного судьи и точную ссылку на первоисточник;
- различие одной выгрузки и сопоставленных реестров;
- отсутствие дублей по УИД и чужих судебных актов;
- `noindex` на ещё не завершённых персональных страницах.

## Почему это не импорт судебных мотивировок

Машиночитаемая выгрузка может сообщать итог и ссылку на акт, но не раскрывать его проверенную мотивировку. По ФЗ № 262-ФЗ отдельные сведения могут не публиковаться; отсутствие доступного полного акта НЕ разрешает сочинить основания решения. Для развёрнутой правовой аналитики нужны реально полученные допустимые тексты и отдельное подтверждение применённых норм и статуса обжалования.

## Контроль версии

Никаких массовых загрузок и деплоев до явного запуска команды пользователем. Все новые файлы и тесты находятся в ветке `infra/coolify-russian-vps`; после публикации проверить GitHub Actions и записать SHA коммита массовой партии.
