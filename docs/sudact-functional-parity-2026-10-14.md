# «Суды России»: функциональный эталон СудАкт и достоверность данных

Дата анализа: 14 октября 2026 года. Статус: работа продолжается в Draft PR #1. Это документ приёмки и реализации, **не заявление о готовом общем реестре**.

## Разделение ролей источников

- **СудАкт (sudact.ru)** — независимый информационный интегратор судебных решений и справочных карточек. Удобный функциональный и UX-ориентир: деление по судебным системам, карточки судов, контакты, судьи, судебная практика и поиск. Сам проект описывает свою работу как интеграцию сведений с официальных сайтов.
- **ГАС «Правосудие» (sudrf.ru) и сайты федеральных судов**, **официальные сайты арбитражных судов (arbitr.ru, домены судов)**, **официальный портал судов Москвы (mos-gorsud.ru)**, **региональные официальные органы по мировым судьям**, **официальное опубликование актов** — доказательные первоисточники для наших собственных проверенных фактов.
- Ссылки на Sudact маркируются как *дополнительный справочный поиск*, не как подтверждение текущей должности, адреса, телефона или законных условий выгрузки.
- В этом выпуске нет автоматического сбора, копирования текстов решений, фотографий или Judge-rosters с СудАкт. Перед таким использованием необходимы отдельно проверенные правила доступа, происхождения данных и повторного использования.

## Что улучшено в этой итерации

1. Пагинация регионального реестра: `GET /api/v1/regions/:region/courts/page?page=N`, 50 записей на страницу, с точным числом опубликованных записей, валидацией параметра и стабильной сортировкой. Старый endpoint сохранён для совместимости.
2. SEO: собственный title/canonical у каждой региональной страницы; включение опубликованных регионов в sitemap; увеличение лимита выгрузки проверенных карточек с 5000 до 50000 (в пределах лимита стандартного sitemap).
3. Структура страницы суда: семантическое меню разделов, официальный код и тип суда, ссылки на первоисточники, видимость отсутствующих данных, справочная ссылка на соответствующий раздел СудАкт для общей юрисдикции / арбитража / мировых судей.
4. CI: тесты пустого регионального списка и отклонения ошибочного параметра page.
5. Офлайн inbox: v2 с SHA-256 исходных байтов и fail-closed проверкой пакета до стадии записи в очередь; ни одно из этих изменений не создаёт официальные данные.

## Остаток до реального завершения

- **Данные:** получить разрешённые официальные выгрузки по каждому субъекту и судебной системе; установить эталон числа действующих судов/участков и сверить уникальные идентификаторы.
- **Редакционная публикация:** по каждому суду отдельно подтвердить актуальные данные. Не превращать исследовательские 206 записей в «206 подтверждённых судов».
- **Судьи:** подтвердить действующие кадровые назначения; нельзя переносить ФИО из стороннего справочника без действующего акта/официального списка.
- **Судебная практика:** отдельно реализовать допустимую загрузку и поиск актов с соблюдением закона о персональных данных и обнародовании судебных актов, не копируя стороннюю базу.
- **Карта и фото:** геокодирование проверенного адреса с редакционной приёмкой, лицензированные фасады.
- **Production:** публичный домен/HTTPS, авторизация CMS, staging/prod, фоновые задания по разрешённым источникам, резервные копии и проверка восстановления.
- **Масштаб SEO:** при потенциальных 50 000+ URL создать sitemap shards/index, чтобы не превышать протокольные лимиты.

## Критерии приёмки

- Все опубликованные карточки имеют проверенный уникальный ID, название, регион, тип, адрес, официальный сайт, источник и дату проверки; наличие дополнительных полей измеряется отдельно.
- Пагинированный список покрывает все опубликованные карточки без скрытой отсечки.
- Судьи и факты из архивных страниц не выставляются действующими без независимой текущей проверки.
- Удаление строки из одного снимка не означает закрытие суда.
- Без действительного официального источника никакой новый суд не появляется в public API и sitemap.
- Массовый импорт работает только из разрешённого канала; ошибки не приводят к автоматической публикации.
- Запуск production возможен только после проверки безопасности, восстановления резервных копий и настоящей доступности инфраструктуры.
