# Однократное подключение VPS к разработке из GitHub: владелец выполняет только Deploy

Дата подготовки: 2026-11-09. Ветка:
`infra/coolify-russian-vps`. **Никаких ключей в чат.**

## Цель и текущий статус

Через доступную GitHub-интеграцию ChatGPT может вносить изменения
в репозиторий и проверять GitHub Actions, но у него **нет прямого SSH
доступа к вашему VPS**. Чтобы запускать приватные скрипты без дальнейших
ручных команд владельца, создаётся узкий шлюз:

```text
ChatGPT -> GitHub commit (ops/vps/request.json)
        -> GitHub Actions test/validate
        -> SSH key from GitHub environment "vps-stage"
        -> non-root sudy-stage on VPS
        -> root-owned forced-command gate
        -> one fixed private preflight of two downloaded JSONs
        -> aggregate GitHub Actions logs, NOT a Deploy
```

По умолчанию **отключено**: `SUDY_VPS_AUTOMATION_ENABLED` не установлен.
Само добавление YAML в рабочую ветку не создаёт доступа.
Веб-сайт, Coolify и база не меняются.

На этом этапе разрешён только
`moscow-private-preflight <commit-sha>`: запуск
`scripts/moscow-bulk-release.sh` **БЕЗ** `--apply` и `--push`.
Схема допускает последующее добавление отдельного проверяемого процесса
публикации одобренных метаданных, но **такого права сейчас нет**.
Следовательно, прямо сейчас это подготовка автономной диагностики,
а НЕ полномочие выкладывать любое судебное дело в производство.

## Однократные действия владельца

### 1. Выделенный ключ, созданный локально (Windows)

В PowerShell на *своём* компьютере:

```powershell
ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\sudy-stage-actions" -C "github-actions-sudy-stage"
```

Для автоматизированного соединения оставьте кодовую фразу пустой,
если среда не использует поддерживаемый агент ключей. Никогда не
пересылайте приватный ключ в ChatGPT, GitHub issues, почту или веб-лог.
Публичную часть `sudy-stage-actions.pub` разрешено копировать.

Создайте на VPS файл `/root/sudy-stage-actions.pub` с **одной строкой**
из публичного ключа. Приватный ключ на VPS не переносите.

### 2. Одноразовая установка ограниченного аккаунта

В проверенном терминале VPS, **после чтения скрипта установки**,
из рабочего каталога репозитория:

```bash
cd /srv/sudy-bulk-work
git pull --ff-only origin infra/coolify-russian-vps
sudo bash ops/vps/install-moscow-operator.sh /root/sudy-stage-actions.pub
```

Требуются `python3`, `python3-venv`, `git`, `useradd`,
`runuser`, `setfacl`, `ssh-keygen`, SSH-сервер.
Если `setfacl` отсутствует, сначала установите штатный пакет ACL
для вашей ОС. Скрипт должен прекращать работу при неизвестном
расположении файлов или существующем специальном пользователе.

Скрипт создаёт **отдельный** `sudy-stage` без sudo и Docker,
root-owned принудительную SSH-команду, отдельный Git checkout в
`/srv/sudy-stage-runner/sud-court-importer` и ACL только на чтение
двух исходных JSON. **Не** выполняет скачивание, импорт, миграции,
`--apply`, `--push` или Deploy. Файлы сайта и production
базы не открываются для записи.

### 3. GitHub Environment с узкими секретами

В репозитории `ymaslen77-tech/sud-court-importer`:
Settings → Environments → создать `vps-stage`.
При возможности ограничьте environment только веткой
`infra/coolify-russian-vps`.

Создайте пять **environment secrets** (не файлы в репозитории):

| Имя | Что указать |
| --- | --- |
| `SUDY_VPS_HOST` | IP или DNS вашего VPS, доступный с GitHub-hosted runner |
| `SUDY_VPS_USER` | `sudy-stage` |
| `SUDY_VPS_PORT` | TCP-порт SSH, обычно `22` |
| `SUDY_VPS_STAGE_SSH_KEY` | Полный текст выделенного **приватного** ключа с вашего ПК, напрямую в GitHub Secret |
| `SUDY_VPS_KNOWN_HOSTS` | Пиннинг реального **публичного host key SSH** VPS в формате OpenSSH `known_hosts` |

Host key необходимо получить с внешнего клиента через `ssh-keyscan`
и **сверить fingerprint** с выводом
`sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` в доверенном
терминале самого VPS. Не доверяйте одному `ssh-keyscan` без сверки.
При нестандартном порте в known_hosts используют `[host]:port`.

В Settings → Secrets and variables → Actions → Variables создайте
`SUDY_VPS_AUTOMATION_ENABLED=true` только после этой проверки.
Секреты никогда не передаются в чат. GitHub ChatGPT-коннектор не
предоставляет мне функции установки этих секретов.

GitHub-hosted runners должны иметь маршрут к SSH VPS. Если сервер
доступен только через частную сеть, не открывайте SSH в Интернет
вслепую: потребуется отдельный согласованный защищённый туннель
или изолированный self-hosted runner.

### 4. Запуск без дальнейших команд владельца

После настройки я меняю только `requestId` в
`ops/vps/request.json` через GitHub. Это вызывает
`.github/workflows/moscow-vps-private-preflight.yml` при push
в рабочую ветку. GitHub проверит заявку и тесты; ограниченный
SSH-шлюз разрешит только приватную сверку. Я смогу читать
обезличенные отчёты из GitHub Actions и продолжать исправления.
Владелец **не запускает импорт вручную**.

Нельзя утверждать, что один успешный тест автоматически разрешает
публикацию всей базы. Для права менять публичные метаданные понадобится
следующий, отдельно проверенный gate «принято → записать только
одобренный JSON в GitHub», с подтверждёнными условиями использования,
политикой обезличивания, откатом и успешным CI. Он будет подготовлен
после первого работающего приватного preflight.

### 5. Coolify: Deploy остаётся за владельцем

У приложения `sudy-web` проверьте выбранную рабочую ветку и
`Auto deploy`. Если хотите оставлять **только ручной Deploy**,
отключите Deploy-on-push в Coolify. Иначе простые изменения GitHub
могут автоматически запускать публикацию, независимо от наших скриптов.

Я не устанавливаю Coolify API токен — для импорта он не нужен.
Не предоставляйте этому шлюзу доступ к паролям базы, ключам Coolify
и полномочия root.

## Ограничения и безопасность

- Сайт суда и судейская база не меняются при preflight.
- Результаты отчёта — только агрегаты; исходные дела остаются на VPS.
- Отказ на неизвестную команду и запрет произвольного пути/флага.
- Для полного текста судебных актов нужны отдельные законные источники,
  проверка статуса публикации и обезличивание.
- GitHub Actions workflow защищён минимальными правами
  `contents: read`; переменная включения — явное действие владельца.
- Секретный ключ ограничен SSH forced command, аккаунт не root,
  нет sudo, нет write-доступа к публичной базе.
