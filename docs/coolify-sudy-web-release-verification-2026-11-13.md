# Выпуск sudy-web в Coolify — проверяемый чек-лист (13.11.2026)

## Точный релиз и уровень готовности

- Репозиторий: `ymaslen77-tech/sud-court-importer`.
- Ветка Coolify: `infra/coolify-russian-vps`.
- Проверенный код до добавления данного проверочного сценария: `6a2e5c8b8473c751ec36879592a5681757b40957`. После объединения сценария использовать **новый** HEAD рабочей ветки, а не старый SHA.
- Приложение **`sudy-web`**, сборка из `Dockerfile.coolify.web`; внутренний порт **3000**.
- Публичный адрес согласно существующему проектному регламенту: `https://sud-russia.ru`; действующий домен и маршрут в Coolify должны быть проверены непосредственно в интерфейсе перед публикацией.
- Содержимое: 35 районных судов, **29 датированных опубликованных составов**, 6 с неполными кадровыми источниками. 27 отдельных реестровых карточек дел, 2 сопоставленные апелляционные регистрации (одна с датированным **назначением** на 19.11.2026), 0 утверждённых текстов мотивированных решений, 0 утверждённых домовых адресных правил. Это рабочий справочник с атрибуцией, а не «все юридические данные окончательно проверены».

## Контроль до Deploy (не выполнять команды на VPS без надобности)

1. Открыть коммит HEAD `infra/coolify-russian-vps`, убедиться, что **CI** и **Moscow GitHub-only data and website checks** на нём завершились `success`. Не использовать только зелёные проверки старых PR.
2. Убедиться в Coolify, что приложение `sudy-web` привязано именно к этому репозиторию и ветке. Проверить метод сборки **Dockerfile** и путь `Dockerfile.coolify.web`, порт 3000, публичный домен, сертификат HTTPS и отсутствие конфликтующих автоматических redeploy. **Не менять API, базу, другие приложения и DNS** ради обновления статического судебного каталога.
3. Сохранить ссылку на предыдущий успешный deployment / возможность rollback в Coolify. Не выполнять миграции БД: эта партия меняет файловые страницы и проверочные скрипты, не схему базы.
4. Выполнить обычное **Deploy** в Coolify для `sudy-web`; дождаться фактического состояния `Running` / `Healthy` и убедиться, что именно этот revision запущен. Если сборка падает, изучить deployment logs и откатить к предыдущему успешно работающему выпуску; не объявлять результат успешным.
5. Сразу после публикации открыть `https://sud-russia.ru/courts/moscow`, `/courts/moscow/judges`, `/courts/moscow/cases`, `/courts/moscow/registry/shcherbinskiy/info/judges` и `/courts/moscow/registry/nikulinskiy/info/cases`. На последней странице назначение апелляции должно быть обозначено как снимок **на 13.11.2026**, а не актуальное решение. 
6. На страницах судей, подборки дел и тематических карточках проверить `noindex` и прямые официальные ссылки. Не снимать ограничения индексации до исполнения issue #62.

## Независимая проверка живого сайта после Deploy

Добавлен сценарий `scripts/check-coolify-web-release.cjs`, который делает **только публичные GET** к строго разрешённым `https://sud-russia.ru` / `www.sud-russia.ru`, проверяет 5 URL, HTTP 200, необходимые имена нового состава, номер апелляции и `noindex` у исследовательских страниц. Он не читает секреты или персональные данные, не управляет Coolify.

Для проверки **из GitHub**, без SSH:
`Actions → Coolify sudy-web release verification → Run workflow → infra/coolify-russian-vps → Run workflow`.
Дождаться завершения двух задач: `release-checker-unit` и `production-readonly-smoke`. Зелёный статус показывает, что ожидаемая исследовательская версия видна на указанном домене и её страницы имеют защиту от индексации. **Не доказывает**, что опубликованы все судебные решения или текущие назначения. При ошибке выяснить фактический домен, редиректы и revision контейнера, не обходить проверку фиктивными утверждениями.

Для обычной разработки `pnpm` или `node` вручную не нужны. При необходимости можно выполнить `node --test scripts/test-coolify-web-release.cjs` локально: он полностью офлайн. `node scripts/check-coolify-web-release.cjs` требует публичного HTTPS.

## Что не подтверждено в текущем рабочем контексте

В подключённых к ChatGPT инструментах доступен GitHub и прежнее Vercel-размещение, **но нет Coolify API / SSH / сеанса браузера владельца для нажатия Deploy**. Ни создание PR, ни зелёный CI не развёртывают `sudy-web`. Нельзя отмечать выпуск как завершённый, пока владелец не запустит кнопку Deploy, не появится статус успешного контейнера и не пройдёт проверка публичного домена. Vercel — другой хостинг, его деплой не подменяет Coolify.

Редакционная блокировка по документам и подсудности сохраняется в https://github.com/ymaslen77-tech/sud-court-importer/issues/62. Полный юридический статус отделён от технической публикации ограниченного справочника.
