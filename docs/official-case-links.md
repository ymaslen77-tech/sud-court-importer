# Привязка официальных судебных дел к проверенным судам

Пилот: Лефортовский районный суд (код 77RS0014), официальный опубликованный пример дела 02-7949/2026, УИД 77RS0014-02-2026-011129-45. Источник: https://m.mos-gorsud.ru/rs/lefortovskij/services/cases/civil/details/fef64000-869b-11f1-ade9-3f611993f6c1

В базе сохраняются только номер, УИД и официальная ссылка, а не ФИО сторон, требования и текст решения. Код из первых 8 символов УИД должен совпасть с внешним кодом ранее верифицированного суда.

## Принцип работы

1. Импорт суда через `federation.py` (например, `mos-gorsud-court`) и отдельная редакционная проверка через `cli.py approve`.
2. Команда `importer/cases.py propose` добавляет ссылку в приватную таблицу `court_case_candidates`. Этот этап не меняет публичную страницу.
3. Редактор сверяет страницу, судебный код и права на использование, затем выполняет `importer/cases.py approve`.
4. В `court_case_references` сохраняется источник, дата и проверяющий. API карточки суда возвращает только подтверждённые записи, максимум 20 ссылок.
5. На странице суда показывается только номер дела, УИД, ссылка на официальный ресурс и дата проверки. Судья не присваивается делу автоматически по инициалам.

## Пример CLI

После реальной публикации проверенного суда с внешним кодом 77RS0014:

```powershell
docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/cases.py propose --court-id <COURT_ID> --uid 77RS0014-02-2026-011129-45 --number 02-7949/2026 --source-url https://m.mos-gorsud.ru/rs/lefortovskij/services/cases/civil/details/fef64000-869b-11f1-ade9-3f611993f6c1 --observer "ФИО редактора"
```

После проверки источник-карточки дела и получения `candidate_id`: 

```powershell
docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/cases.py approve --candidate-id <CANDIDATE_ID> --reviewer "ФИО редактора" --attest-current --attest-reuse-rights
```

Указанные идентификаторы в угловых скобках должны быть заменены фактическими. Команды не выполнялись на компьютере пользователя.

## Ограничения

- Реальная массовая загрузка судебных актов и полнотекстовый поиск ещё не реализованы: требуется подтверждённый формат и условия использования каждого источника.
- Необходимо отдельное проектирование персональных данных, ограничений доступа, идентичности участников и анонимизации актов.
- По одному УИД и инициалам нельзя надёжно привязать дело к персональной карточке судьи.
- В CI используется временная база: тестовое редакционное подтверждение не означает публикацию на рабочем сервере.
