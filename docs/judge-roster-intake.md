# Поэтапный сбор судей: предварительные списки, затем подтверждённые назначения

## Назначения нельзя выводить из простого списка ФИО

Официальная страница судей может содержать список лиц, телефоны и сведения об указах о назначении. Но дата обновления страницы не означает, что на текущий день не было перевода, отставки или замены.

Добавлены две ступени:

1. `court_staff_roster_batches` и `court_staff_roster_rows`: закрытый снимок сведений из одной официальной страницы. У каждой строки есть ФИО, указанная должность и при наличии реквизиты указа. Отсутствует прямой вывод в публичный API.
2. `judges` и `judicial_appointments`: только после проверки редактором личности, актуальности назначения и официальных документов. Повторный судья или однофамилец не должен объединяться по одному имени.

## Первый пилот

Источник: https://www.mos-gorsud.ru/rs/lefortovskij/structure/judges

Официальный список Лефортовского районного суда содержит **11 имён**, даты и номера указов. На странице указано обновление **22.04.2026**; эта дата относится к странице, а не к индивидуальной проверке каждого назначения на октябрь 2026 года.

Файл `importer/seeds/lefortovsky-judges-official-page-unreviewed.json` сохраняет имена и реквизиты указов **для проверки**, без неподтверждённых актуальных дат начала полномочий, внутренних идентификаторов, квартир или личных телефонов. Он не включает имена присяжных и участников дел.

Чтобы загрузить после обновления локального проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\apply-import-migration.ps1
Copy-Item importer\seeds\lefortovsky-judges-official-page-unreviewed.json data\import\lef-roster.json
docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/roster.py validate /input/lef-roster.json
```

Команда `stage` должна выполняться только после сверки страницы ответственным редактором и фактической даты получения:

```powershell
docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/roster.py stage /input/lef-roster.json --captured-on 2026-10-13 --reviewer "Ответственный редактор" --attest-source-observed
```

Дата `--captured-on` — дата фактического чтения источника; её нельзя копировать без проверки. Даже при успешном staging будет `published: 0`.

Для подтверждения конкретного действующего назначения впоследствии используется `importer/judges.py nominate/approve/close`. Проверить: указ действующий, лицо то же, суд и должность совпадают; при недостаточных доказательствах не утверждать запись.

## Масштабирование

- Получать только разрешённым способом официальные страницы состава судов.
- Использовать отдельные форматные адаптеры каждого портала вместо универсального угадывания HTML.
- Сохранять исходный URL, дату публикации/обновления, контрольную сумму и дату реальной проверки.
- При изменении страницы создавать очередь проверки, но не выводить «судья уволен» только из отсутствия ФИО.
- В каждой карточке судьи показывать дату последней проверки, назначение, источник и историю должностей; при устаревшем свидетельстве выводить предупреждение или скрывать сведения.
- После появления проверенных действующих судов связывать кадровые сведения с устойчивыми идентификаторами через отдельную редакционную проверку.

Ни автоматическая сверка 11 ФИО, ни полный общероссийский реестр персонального состава пока не достигнуты.
