## Правила юридической приёмки (обязательные)

1. Не объявлять официальный список судей текущим кадровым составом без проверки.
   Публикация в прошлом не удостоверяет неизменность полномочий сегодня.
2. Различать «официальная запись в реестре» и «проверенный оригинал решения».
   Не выводить мотивировку, статьи закона или исход жалобы из метаданных.
3. При конфликте между двумя официальными страницами не брать номер телефона
   или адрес автоматически. Фиксировать оба источника, дату, специальный
   вид связи и ставить поле на дополнительную сверку.
4. Защищать данные сторон, закрытые категории дел и тексты с запретом
   публикации. Оригиналы остаются в приватном хранилище.
5. Автоматически принимать совпадающие сведения только по правилам
   `importer/moscow_source_acceptance.py`: разные официальные
   документы/публикаторы, подтверждённые снимки и отсутствие разночтений.
   Автоматическая приёмка метаданных сама по себе не означает автопубликацию.
6. Источник должен быть доступен для проверки непосредственно у факта.
   Внутренние переходы приоритетны, но ссылка на источник не блокируется
   искусственными обязательными страницами.
7. Не допускать индексации тонких, непроверенных и дублирующих карточек
   только ради числа страниц. Текущие новые карточки области — `noindex`.

## Локальный приватный полный preflight на VPS — НЕ ПУБЛИКОВАТЬ

Владелец уже разместил оригиналы двух гражданских выгрузок в
`/srv/sudy-private/moscow-open-data/`. После успешного полного CI и
контроля `df -h /srv`, если подтверждены условия источника, выполнить:

```bash
cd /srv/sudy-bulk-work
git pull --ff-only origin infra/coolify-russian-vps
bash scripts/moscow-bulk-release.sh \
  --first /srv/sudy-private/moscow-open-data/1577116594824-casesgroupfirstcivilhxvgb.json \
  --appeal /srv/sudy-private/moscow-open-data/1577117744056-casesgroupmgsappealcivilwtxga.json
```

Это создаёт приватный SQLite-индекс и отчёт, без `--apply`,
`--push` и без Deploy. Большие JSON читаются потоково через ijson.
Контролировать доступное место, лимит строк, сроки обработки и отсутствие
персональных данных в итоговой публичной модели.
Отчёт не является юридической приёмкой каждого судебного решения.
Первый запуск с настоящими выгрузками может выявить дополнительные
форматы полей; несовместимости исправлять отдельными тестами.

## Не закрытые требования

- Завершить восемь недостающих полных списков судей Москвы, затем повторно
  сверить все 35 списков с актуальными официальными кадрами.
- По документально доступным оригиналам составить проверенные краткие
  обзоры решений с точными ссылками на нормы и отдельными результатами
  обжалования. Запрещённые акты не копировать.
- Провести полный приватный индексный прогон двух реестров Москвы и
  обработать причины карантина, не расширяя проверки на другие категории
  по аналогии без анализа их собственных JSON-схем.
- Постепенно дополнить областные карточки индивидуальными сведениями
  и вторым официальным подтверждением изменяющихся реквизитов.
- Включить регулярное отслеживание через одобренный workflow после
  проверки условий портала: schedule GitHub Actions работает только
  с default branch. Файл в рабочей ветке сам по себе ничего не запускает.
- После CI проверить деплой, HTML/meta/robots/sitemap, доступность
  источников и корректность маршрутов. Не применять Deploy без согласования.

Ни один из перечисленных открытых пунктов не может быть объявлен закрытым
по одним лишь модульным тестам или успешной сборке.
