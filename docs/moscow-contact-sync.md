# Москва: проверенная выгрузка контактов и синхронизация

## Подтверждённый первоисточник

- Официальный портал открытых данных судов Москвы: https://data.mos-gorsud.ru/ .
- В реестре портала указан отдельный набор в категории **«Контакты и часы приёма»**. Это подтверждает существование тематического набора, но не подтверждает доступность публичного API или фиксированного URL ZIP/JSON.
- Условия повторного использования: https://data.mos-gorsud.ru/terms-of-use . **Перед загрузкой нужно прочитать их в браузере:** на момент подготовки автоматическое прочтение страницы затруднено из-за JavaScript/сетевого ограничения. Нельзя выдавать доступность сайта за разрешение автоматизированного скачивания.
- Официальный список объектов на карте (ручная перепроверка): https://www.mos-gorsud.ru/courts . Он не является лицензией на массовое копирование изображений.

## Получение исходных данных

1. Откройте официальный реестр через браузер. Выберите конкретный набор «Контакты и часы приёма». Запишите URL карточки набора вида `https://data.mos-gorsud.ru/opendata/<REAL_DATASET_ID>` и фактическую дату получения.
2. Проверьте условия использования: доступный формат экспорта, необходимость регистрации, ограничения на повторное использование и автоматическое обращение к серверу.
3. Выгрузите разрешённым способом JSON и нормализуйте **только подтверждённые поля** в виде массива объектов:

    [{
      "courtCode": "77RS0001",
      "courtName": "НАЗВАНИЕ ИЗ ОФИЦИАЛЬНОГО НАБОРА",
      "courtAddress": "АДРЕС ИЗ ОФИЦИАЛЬНОГО НАБОРА",
      "courtTelephone": "ТЕЛЕФОН ИЗ ОФИЦИАЛЬНОГО НАБОРА",
      "courtEmail": "ПОЧТА ИЗ ОФИЦИАЛЬНОГО НАБОРА",
      "courtSiteUrl": "https://www.mos-gorsud.ru/rs/REAL_SLUG"
    }]

Пример **схемы**, не настоящий суд с этим кодом. Реальный экспорт портала может иметь другие названия полей — не объявлять конвертер готовым без проверки фактического файла. Данные по каждому суду сверять с его официальной веб-страницей.

## Новый приёмник JSON (не скачивает сеть)

Сохраните нормализованный файл в `data/import/moscow-contacts.json` в установленной папке проекта. Проверьте:

    docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/moscow_sync.py validate /input/moscow-contacts.json

После реального подтверждения условий и источника:

    docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/moscow_sync.py sync /input/moscow-contacts.json --dataset-url https://data.mos-gorsud.ru/opendata/REAL_DATASET_ID --captured-on 2026-10-13 --reviewer "Ответственный редактор" --attest-reuse-rights

Замените `REAL_DATASET_ID` на действительный идентификатор официального набора, а дату — на фактическую дату скачивания. Подтверждение прав — осознанное действие, не формальный обход защиты.

`sync` делает:

- строгую проверку судебного кода, URL суда, адреса и базовых контактных полей;
- SHA-256 первичного JSON и неизменяемый staging по источнику;
- сравнение с предыдущим снимком *того же набора*;
- предложения «телефон изменился / email изменился / новый суд» в `court_registry_diff_items`;
- никаких изменений публичной таблицы `courts` до отдельного редакционного подтверждения.

Повторная загрузка того же файла не создаёт дублей. В тестах используются только **вымышленные** суды с явной тестовой меткой.

Очередь для редактора:

    docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/registry_diff.py pending --limit 100

## Автоматическое обновление — границы готовности

Можно автоматизировать обработку **уже полученных** файлов и согласование изменений. Пока НЕ запущен сетевой загрузчик московского набора, потому что ещё не подтверждены его конкретный машиночитаемый URL и условия автоматического обращения. Нет оснований заявлять, что система круглосуточно получает новые контакты с официального портала.

Следующее обязательное подтверждение: получить настоящую структуру одного набора и документированный законный способ регулярного экспорта; только после этого реализовать планировщик, условные HTTP запросы, схему полей и реальное обновление без ручного получения файла.

## Опциональная автоматическая обработка входящих файлов

Это локальный **файловый приёмник**, а не паук: регулярное скачивание с судейских сайтов/порталов пока не разрешено и не настроено. Раздел активируется только после того, как оператор вручную получил доступный официальный файл и проверил условия использования.

1. Нормализованный JSON поместите в `data/import/inbox/moscow-2026-10-13.json`.
2. Рядом создайте `data/import/inbox/moscow-2026-10-13.manifest.json` со следующим содержимым:

```json
{
  "format": "moscow-contacts-v1",
  "file": "inbox/moscow-2026-10-13.json",
  "dataset_url": "https://data.mos-gorsud.ru/opendata/REAL_DATASET_ID",
  "captured_on": "2026-10-13",
  "reviewer": "Ответственный редактор",
  "reuse_rights_confirmed": true
}
```

Замените `REAL_DATASET_ID` на URL реального набора. Поле `reuse_rights_confirmed` разрешено устанавливать в `true` только после личной проверки правил источника. Дата должна соответствовать фактическому получению выгрузки.

Сначала выполните безопасную проверку без записи в PostgreSQL:

```powershell
docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/inbox.py check
```

Для однократной закрытой загрузки:

```powershell
docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/inbox.py stage
```

Для периодической обработки имеющихся файлов без новых сетевых запросов:

```powershell
docker compose -f compose.local.yaml --profile intake up -d court-intake
docker compose -f compose.local.yaml logs --tail 30 court-intake
```

Контейнер читает `/input/inbox` каждые 6 часов, поэтому он работает **только пока включён Docker-хост**. Повторные одинаковые данные не создают новых пакетов: форматирование и порядок полей нормализуются перед расчётом batch hash. Отдельная контрольная сумма сохранена для входного нормализованного JSON.

Не храните старые манифесты в активном inbox более 30 дней: перенесите их в локальный архив после проверки, иначе просроченные метаданные будут отклоняться. Ошибки отображаются в логах, не приводят к публикации и не заменяют существующие verified-карточки.

Важно: `data/import/inbox` — локальная папка для уже доступных оператору файлов; сервис не обходит robots.txt, не извлекает персональные назначения из произвольных страниц и не скачивает изображения.
