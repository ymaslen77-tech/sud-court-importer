## Новый подтверждённый пилот исходных судебных записей

В `importer/seeds/novosibirsk-federal-additional-official-unreviewed.json` помещены **26 дополнительных исходных кандидатов** из официальной региональной выдачи ГАС, помимо прежних десяти. Данные соответствуют доступной веб-копии страницы, но не являются подтверждением текущего состояния судебных органов на дату создания файла. Адреса/телефоны/HTTP-ссылки на сайты перед публикацией требуют отдельной независимой проверки. Идентификаторы не должны автоматически создавать публичные карточки.

Сумма предварительных исходных записей проекта стала **232 (206 прежних + 26 дополнительных)**. Категории исходного корпуса могут пересекаться; это НЕ 232 новых или проверенных суда.

Проверка кандидатов:

```powershell
docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/federation.py validate /work/importer/seeds/novosibirsk-federal-additional-official-unreviewed.json --registry sudrf-federal
docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/seed_audit.py
docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/source_channels.py
```

Третья команда должна показывать `permissioned_machine_feeds: 0`; пока нет документального основания включать автоматическое скачивание. При этом `importer/inbox.py` допускает **только уже разрешённым способом полученные** файлы со строгим источниковым манифестом, SHA-256 и отдельным редакционным утверждением.

## Что необходимо до разрешённого автоматического наполнения

1. Действительный **конкретный URL и версия схемы** машинной выгрузки каждого судебного реестра; для отдельных регионов документировать исключения и неполноту.
2. Подтверждение оператора источника или документированные условия, допускающие именно запланированный регулярный машинный доступ и повторное использование; правила robots, допустимая нагрузка и лимиты.
3. Хранение исходного ответа неизменяемо, SHA-256, даты и URL, retry/backoff, условные запросы, отказ при изменении формата или прав доступа.
4. Проверка каждой записи/поля редактором по актуальному первоисточнику. Смена статуса реестра или пропавший суд не может выводиться из одного неполного снимка.
5. Для круглосуточной работы — отдельный сервер/домен, секреты, резервные копии и мониторинг; local Docker выключается вместе с компьютером.

## Запрос оператору — подготовка

При отсутствии опубликованного машинного интерфейса следует официально запросить у владельца ресурса:

- возможность и правила регулярного получения актуального **списка действующих судов** по всем регионам с кодом суда, регионом, уровнем, адресом и официальной ссылкой;
- доступность JSON/CSV/ZIP выгрузки, версию схемы, периодичность, полноту, правила изменений/упразднений, ограничения запросов;
- условия повторного использования в общедоступном справочнике, требования к атрибуции и обработке данных;
- отдельные условия для сведений о судьях и судебных актах.

Пока запрос не согласован, считать все сети **permission pending**, не отключать защитные ограничения и не вводить 24/7 scraper.

## Проверка в коде

`importer/sources/official-channels.json` содержит машиночитаемую инвентаризацию. `importer/source_channels.py` откажет считать запись `approved_feed` без документального URL, подтверждения условий, флага разрешённого автоматического доступа и права повторного использования. Это техническая проверка полноты метаданных, **не самостоятельное юридическое подтверждение**. Каждое положительное разрешение должно быть подтверждено реальными документами операторов, а не поставлено разработчиком по предположению.
