# Этапы до эксплуатации общероссийского справочника судов

## Граница готовности

Этот файл — список **проверяемых условий**, не обещание, что
каждый этап уже выполнен. Действующая ветка остаётся Draft.

| Этап | Что реализовано | Критерий реального завершения | Блокирующие зависимости |
|---|---|---|---|
| 1. Источники | Sudrf / Moscow offline-интеграции, проверки источников и формата | Договорённый или общедоступный машиночитаемый канал для каждого реестра + подтверждение условий использования и периодичности | URL/условия/доступ к официальным выгрузкам |
| 2. Полный реестр | Таблицы типов, регионов, snapshots, dedup и diff, пилотные выборки | Уникальные подтверждённые суды и участки по каждому субъекту и виду; отчёт о полноте отдельно по реестрам | Полные выгрузки и редакторы |
| 3. Судьи/контакты | Истории appointments, field proposals, сохранение официальных источников | Проверенный состав конкретного суда, телефоны, часы, даты назначения и смена статуса с документом | Официальные документы и подтверждение личности |
| 4. Редакционный кабинет | Закрытый обзор /editor с очередями, источниками, монитором и логами импортёра | Защищённые многопользовательские роли, просмотр досье, управление утверждением с проверкой конфликтов и аудитом входа | IdP, MFA, HTTPS |
| 5. Гео/изображения | Модель координат, OSM по клику, media provenance, EXIF removal | Реальные проверенные координаты и лицензированные фото по публикуемым судам | Право на фото и точная привязка здания |
| 6. Постоянный мониторинг | Опциональные локальные задачи в Docker, diff и очередь | Круглосуточный хост, доступность источников, уведомления, алерты, измеряемое время обнаружения и обработки | Сервер, разрешённые сетевые обращения |
| 7. Судебная практика | Подтверждаемые ссылки на дела, без неподтверждённых участников | Достоверные связи суд–дело–судья–акт, разрешённый источник данных, полнотекстовый поиск | Доступный массив судебных актов |
| 8. SEO/публикация | Метаданные, canonical, noindex для пустых страниц, sitemap | Наполненные verified-страницы, HTTPS-домен, мониторинг поисковой индексации, резервное копирование/восстановление | Этапы 1–7 и продакшен-инфраструктура |

## Что действительно проверяется автоматическими тестами

- PostgreSQL, API, Next.js, импортёры, миграции и smoke-доступность страниц;
- невозможность автоматической публикации staging court rows;
- идемпотентность повторных файлов и сравнение изменившихся контактов;
- отсутствие ложного «закрытия суда» из неполных официальных списков;
- статус фамилий судей только при утверждённом appointment;
- защищённость /editor и внутреннего API при отсутствии секретов;
- журнал и отчёт о последних попытках загрузки файлов.

Это тесты программной реализации, не заверение в фактической актуальности
всех судов России или юридической допустимости источника.

## Необходимые материалы и инфраструктура

- Подтверждённые условия использования и машиночитаемые URL источников
  для региональных и федеральных судов, мировых участков и арбитража.
- Система редакторского подтверждения: ответственное лицо/роль и
  протокол сверки источников. Без этого нельзя переводить незнакомые
  записи из staging в публичные.
- Секреты, домен, HTTPS, изолированная PostgreSQL, внешний бэкап и
  право доступа к круглосуточному хосту, если требуется онлайн-сервис.
- Лицензированные фасадные фотографии с указанием автора и ссылки
  на действующие условия использования. Не подменять их нейрогенерацией
  или снимками коммерческих карт.
- Проверяемый реестр судебных дел/актов или официальный экспорт
  для последующего поиска по судье, процессуальной статье и инстанции.

## Недопустимые замены

- Тестовые записи из CI не являются опубликованными судами.
- 174 предварительные исходные записи не означают 174 проверенных суда.
- Появление HTML-сигнала у мониторинга не означает смену председателя.
- Само наличие /editor не превращает его в production CMS.
- Сайт localhost:4173 не является круглосуточным публичным сервисом.

## Текущий релизный принцип

Разработка проходит в `feat/001-court-portal-foundation` и Draft PR №1,
без merge в `main` до завершения приёмки. Любое решение о публикации
отдельной карточки требует подтверждения первоисточника, даты и прав.
