# Общероссийский каталог судов — источники, охват, качество

## Подтверждённые официальные каталоги

1. **Федеральные суды общей юрисдикции.** ГАС РФ «Правосудие»:
   https://sudrf.ru/index.php?act=go_search&id=300&searchtype=fs
   Справочник содержит классификационные коды, названия, почтовые адреса,
   контакты и ссылки на сайты. В том числе встречаются военные суды и
   суды субъектов РФ. Проверять каждую запись и тип суда индивидуально.
2. **Судебные участки мировых судей.** ГАС «Правосудие»:
   https://sudrf.ru/index.php?act=go_ms_search&id=300&searchtype=ms
   Собственный классификационный код участка. Назначение мирового судьи и
   перечень адресов подсудности — **отдельные** регулярно меняющиеся сведения.
3. **Арбитражные суды.** Федеральный реестр:
   https://arbitr.ru/?id_doc=20563&id_sec=353
   Отличать арбитражный суд субъекта РФ, апелляционный суд, суд округа и
   Суд по интеллектуальным правам. Код суда не следует подменять регионом
   территориальной юрисдикции.
4. **Москва.** Дополнительный официальный набор контактов:
   https://data.mos-gorsud.ru/opendata
   Отдельный парсер `importer/contacts.py`, с той же ручной проверкой.

Эти страницы служат навигационными источниками. **Наличие страницы не
означает подтверждения возможности массовой выгрузки и повторного использования**.
Перед массовым извлечением необходимо проверить правила использования,
robots/нагрузку, формат экспорта и допустимые методы доступа. Не обходить
ограничения сайтов.

## Поля каждой будущей карточки

| Блок | Поля | Проверка перед публикацией |
|---|---|---|
| Идентичность | Классификационный код, название, тип, статус | Источник реестра и реорганизации |
| География | Субъект, адрес, координаты | Сверка адреса; адрес **не равен** подсудности |
| Контакты | Телефон, e-mail, официальный сайт | Фактический сайт суда, дата сверки |
| Состав суда | Председатель, заместители, судьи, полномочия | Назначения и даты по отдельным актам |
| Приём | Часы работы, расписание приёма, канцелярия | Актуальная публикация конкретного суда |
| Подсудность | Предметная/территориальная/инстанционная | Нормы права, географические исключения |
| Процесс | Виды дел, подача, пошлины, реквизиты | Правила, применимые на дату обращения |
| Судебные акты | Дела, документы, номера, даты, инстанция | Первичный акт, редактирование персональных данных |
| История | Изменения названия, переезды, ликвидация | Реестровая запись и нормативное основание |

Неточность данных должна приводить к понижению статуса на **непроверено**,
а не к выдуманным значениям. Старые и новые названия судов нельзя
автоматически склеивать только по совпадению строк.

## Готовый технический путь

```text
официальная страница → полученный разрешённым способом файл
   → нормализованное JSON-представление со ссылкой на источник
   → strict validate → закрытая стадия court_import_rows
   → проверка актуальных сведений редактором
   → approve одной карточки → courts verified → каталог / API
```

Общий парсер находится в `importer/federation.py`; доступны реестры:
`sudrf-federal`, `sudrf-magistrate`, `arbitr-courts`.

`importer/seeds/novosibirsk-federal-official-unreviewed.json` содержит
**10 реальных записей**, вручную перенесённых из выдачи ГАС по
Новосибирской области. Это **снимок исходной публикации, а не
подтверждённый актуальный справочник**. Файл не утверждается и не
публикуется автоматически. Он полезен как первый источник реальных
кандидатов и тест корректности парсинга.

### Проверка и загрузка

1. Получите JSON с указанными полями из проверенного официального
   первоисточника допустимым способом. Для каждой выгрузки нужен
   **один конкретный URL** `sourceRecordUrl`.
2. Поместите файл в `data/import/<file>.json` на локальном хосте.
3. При изменении структуры БД запустите существующий
   `scripts/apply-import-migration.ps1`.
4. Из корня репозитория:

```powershell
docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/federation.py validate /input/courts.json --registry sudrf-federal
docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/federation.py stage /input/courts.json --registry sudrf-federal
```

Для файлов иных реестров используйте соответственно `sudrf-magistrate`
или `arbitr-courts`.

5. Убедитесь, что `published: 0`. Для единичного утверждения применяйте
   `importer/cli.py approve` с точной проверенной ссылкой суда,
   реальной датой проверки, именем проверяющего и требуемыми подтверждениями.
   См. `docs/moscow-import.md` — форма команды аналогична.

## Требования к общероссийским JSON-записям

```json
{
  "courtCode": "54RS0012",
  "regionCode": "54",
  "regionName": "Новосибирская область",
  "courtName": "Барабинский районный суд Новосибирской области",
  "courtType": "Районный суд",
  "courtAddress": "632334, Новосибирская обл., г. Барабинск, пер. Индустриальный, д. 7",
  "courtTelephone": "(383) 612-91-37, 240-95-26",
  "courtEmail": "barabinsky.nsk@sudrf.ru",
  "courtSiteUrl": "http://barabinsky.nsk.sudrf.ru",
  "sourceRecordUrl": "https://sudrf.ru/index.php?act=go_search&court_subj=54&id=300&searchtype=fs"
}
```

Пример иллюстрирует **формат** и данные, опубликованные в указанной
региональной выдаче, но не утверждает их актуальность на момент просмотра.
Сайт суда может использовать HTTP, однако страница первичной выдачи
для доказательства происхождения должна использовать HTTPS.

## Учёт охвата и следующие задачи

- Составить полный список  субъектов и категорий судебной системы по
  документированным официальным реестрам (не по догадкам).
- Для каждой пары регион + тип фиксировать дату снимка, количество
  кандидатов, число проверенных карточек и непроверенный остаток.
- Сверять переименования, прекращение деятельности и перемещения.
- Добавить надёжные выгрузки, соблюдающие правила сайтов и лимиты, а
  затем регулярно сравнивать снимки.
- Отдельно подключить судей и назначения, графики приёма, судебные
  акты и проверенные границы подсудности; не выводить пустые «SEO-карточки».

**Статус на сегодня:** общероссийский валидатор, единый staging и начальная
доказательная выборка готовы. Полный охват России и массовая
верификация **не заявляются** до фактического импорта и проверки.
