# Индивидуальные страницы исследовательских судебных записей

## Реализовано (14 октября 2026)

Создан отдельный слой **исследовательских страниц** из уже сохранённых локальных снимков открытых официальных реестров. Он позволяет проверять дизайн, навигацию и наполненность **до** публикации окончательно подтверждённой записи.

| Субъект | Источник | Предварительных индивидуальных страниц |
| --- | --- | ---: |
| Хабаровский край | Региональный перечень судебных участков ГАС «Правосудие» | 75 |
| Новосибирская область | Региональная выдача федеральных судов ГАС «Правосудие» | 36 |
| Омская область | Региональная выдача федеральных судов ГАС «Правосудие» | 40 |
| **Всего** | | **151** |

Первые 76 карточек имеют из исходных официальных региональных перечней название, код, адрес, телефон, e-mail и официальный сайт суда. У 75 судебных участков Хабаровского края есть код, название и **персональная ссылка на официальный сайт**, указанные в [региональной выдаче ГАС «Правосудие»](https://sudrf.ru/index.php?act=go_ms_search&court_subj=27&id=300&ms_type=ms&searchtype=ms&var=true). **Адрес, телефон и e-mail** в исходном списке не приведены: эти поля остаются пустыми. Ссылки на сайты указаны в формате HTTP как в официальной выдаче; фактическая доступность и актуальные контактные сведения требуют отдельной проверки.

Примеры адресов локального сайта (домен здесь не указан, поскольку production не развёрнут):

- `/courts/region-54/sud-54rs0012` — Барабинский районный суд
- `/courts/region-55/sud-55os0000` — Омский областной суд
- `/courts/region-27/sud-27ms0001` — судебный участок № 1 Хабаровского края

## Граница доверия и SEO

- Все 151 страницы **предварительные**: `robots: noindex`, нет URL в `sitemap.xml`.
- Они не участвуют в счётчике `verified` и в PostgreSQL `courts` не появляются. На каждой странице явно указана непроверенная актуальность.
- После редакционного подтверждения через существующий DB pipeline маршрут `/courts/<region>/sud-<code>` может стать полноценной подтверждённой карточкой, если slug совпадает с официальным идентификатором.
- При отсутствии публичного API страница предварительной записи остаётся доступна из встроенного локального набора; проверенный ответ БД имеет приоритет над предварительными данными.
- Дублирование исходных файлов в `apps/web/app/lib/research-courts.json` и `research-magistrates.json` допускается только при сохранении происхождения. CI `test_research_preview.py` сверяет поля с исходными файлами, официальные сайты мировых участков с региональной выдачей, коды и отсутствие вымышленных контактов.
- Нельзя утверждать, что массовая исследовательская база — это 151 проверенный действующий суд, или что весь общий набор из 273 записей имеет одинаковую полноту.

## Как проверить локально

После запуска Docker Compose:

```powershell
docker compose -f compose.local.yaml up -d --build
```

Откройте `http://localhost:4173/courts`, затем выберите Хабаровский край, Новосибирскую или Омскую область в блоке исследовательских регионов. Найдите суд через `/search` по названию или коду.

CI дополнительно проверяет HTML региональных страниц, конкретные карточки, отсутствие `/courts/region-54/sud-54rs0012` в sitemap и наличие `noindex`.

## Что отсутствует для полноценного запуска целевых SEO-страниц

1. Проверка на дату публикации официального адреса, телефонов и сайта конкретного суда.
2. Законное подтверждение состава судей и полномочий, включая назначения, перевод и прекращение статуса.
3. Подача документов, часы работы, подсудность, реквизиты и специальные контакты конкретного суда.
4. Геокодирование подтверждённого адреса, лицензированное фото фасада.
5. Разрешённые официальные судебные акты и связанная практика.
6. Запуск постоянного хоста с рабочей PostgreSQL и проведённой редакционной приёмкой. Сам по себе успешный CI публикует только код и не обновляет пользовательскую БД.

**Автоматические загрузчики и регулярное сканирование открытых источников в этой итерации не включаются по решению владельца проекта.**
