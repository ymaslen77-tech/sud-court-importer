# Универсальный импорт географических границ подсудности

## Назначение

Один программный механизм для регионов РФ и категорий судов, без повторного программирования под каждую карточку. Конвертация и проверка выполняются **однократно на версии официального приложения**. Пользовательский поиск впоследствии использует подготовленные и **отдельно юридически утверждённые** границы, а не открывает заново PDF или сайты судов.

**Этот выпуск — исследовательский импортёр и контроль геометрии, не выпуск новой точной подсудности.** В production по-прежнему 138 ожидаемых оригинальных приложений закона Новосибирской области № 149-ОЗ: ни одного полученного официального оригинала здесь нет.

## Источники и входные файлы

Входные данные:
- Подлинный PDF/документ приложения из официального сайта (получение оригинала и юридическую актуальность нужно подтвердить отдельно).
- `manifest.json` с кодом региона, URL официального источника, заявленной SHA-256 первичного документа, датой исследования, видом источника, номером приложения к зарегистрированному акту, явной EPSG:4326 и описанием способа преобразования.
- `boundaries.geojson`: GeoJSON FeatureCollection только из Polygon/MultiPolygon, с `properties.feature_id`, необязательным **предварительным** `court_code` и замкнутыми координатными кольцами в WGS84 (долгота, широта).
- Для приложений с координатными таблицами — `source.csv` с колонками `feature_id,polygon_id,ring_id,vertex_order,lon,lat,court_code`; адаптер преобразует CSV в GeoJSON и проверяет весь результат.

Импортёр **не извлекает координаты автоматически из PDF**, не геокодирует текст и не угадывает систему координат. Наличие координат в национальной/местной системе требует отдельного документированного перепроецирования. Эти действия выполняются отдельными адаптерами под формат официального документа; единая стадия сохранения от формата исходного PDF не зависит.

### CLI

```bash
# Без БД: формальная проверка входных GeoJSON и происхождения
python importer/jurisdiction_geometry.py inspect manifest.json boundaries.geojson

# При необходимости конвертировать нормализованную официальную таблицу:
python importer/jurisdiction_coordinates_csv.py source.csv boundaries.geojson --crs EPSG:4326

# Повторяемое сохранение исследовательского пакета в Neon/PostGIS:
DATABASE_URL='...test...' python importer/jurisdiction_geometry.py stage manifest.json boundaries.geojson --confirm

# Отчёт о пересечениях площадью более 1 м²:
DATABASE_URL='...test...' python importer/jurisdiction_geometry.py audit --region 54
```

**Не копировать тестовые примеры в production.** Синтетические файлы `importer/tests/fixtures/synthetic_boundary_*` специально содержат конфликтующие полигоны и нулевой SHA документа; они не являются геоданными Новосибирской области.

## Проверки качества

1. HTTPS и строго разрешённые домены официальных источников: pravo.gov.ru, publication.pravo.gov.ru, sudrf.ru и поддомены sudrf.ru.
2. Сверка номера приложения с существующей записью `court_jurisdiction_annex_backlog` и кода региона; независимая сверка фактического PDF-хеша отдельно отмечается как не проведённая.
3. Предельные размеры файлов, число объектов, число вершин, уникальные идентификаторы и допустимые два числа каждой точки.
4. CRS EPSG:4326 без автоматических догадок; отказ для невалидных полигонов, самопересечений, незамкнутых колец и нулевой площади.
5. PostGIS: MultiPolygon 4326, `ST_IsValid`, `ST_Area`, GiST индекс, сравнение пересечений через `ST_Intersection(... )::geography`.
6. Атомарная, повторяемая загрузка по SHA-256 GeoJSON: второй запуск не дублирует пакет. Наличие пересечений попадает в диагностический отчёт, **не** приводит к автоматическому исправлению границ.
7. На всех новых таблицах жёсткие `CHECK(research_only)`, `CHECK(permitted_for_routing=false)`. Ни `court_jurisdiction_units`, ни публичный `approvedRules` не меняются.

## Схема БД

Миграция `018_court_boundary_geometry_staging.sql` создаёт:
- `court_boundary_import_batches`: первоисточник, дата, SHA-256 входного GeoJSON и заявленный SHA оригинала, связь с актом и номером приложения, происхождение конвертации, запрет использования в поиске;
- `court_boundary_research_polygons`: связанная геометрия, идентификатор объекта и предварительный код суда, пространственный индекс, запрет использования в поиске.

## Что ещё необходимо для настоящего адресного поиска

- Получить и проверить официальные приложения и установить, в какой системе координат опубликованы исходные точки.
- Конвертировать официальные файлы в проверенный EPSG:4326 GeoJSON, не допуская подмены исходных цифр.
- Проверить статус конкретного суда/участка, юридическое действие акта и соответствие номера приложения.
- Разрешить пересечения и изменения границ, подтвердить полноту покрытия.
- Сопоставлять пользовательские адреса с точками только через проверенный геокодер; отдельно контролировать точность дома, корпуса и пограничное положение точки.
- После **документированной редакционной аттестации** создать отдельную разрешённую к использованию версию границ и интегрировать её с однозначным определением суда. **Это отдельный будущий этап, не выполняемый текущей миграцией.**

## Приёмка

Синтетические модульные тесты импортёра (включая повреждённые кольца, CRS и поддельные официальные хосты), реальный CI PostGIS (пересечение двух полигонов, повторная загрузка и запрет переключения `permitted_for_routing`), полная сборка существующего проекта, тестовая ветка Neon до production.

Массовый сетевой сбор и автоматическая публикация не включаются. Серверные расходы при обычном пользовательском поиске не увеличиваются, пока исследовательские данные не станут одобренным реестром.
