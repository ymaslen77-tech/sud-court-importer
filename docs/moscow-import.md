# Пилотный импорт судов Москвы

## Проверенный источник

На официальном [портале открытых данных московских судов](https://data.mos-gorsud.ru/opendata)
имеется набор «Контакты и часы приема граждан в судах общей юрисдикции города Москвы».
Он содержит поля `courtCode`, `courtName`, `courtAddress`, `courtTelephone`,
`courtEmail`, `courtSiteUrl` и сведения о работе подразделений.

**Важно:** адрес прямого JSON-экспорта и его текущие условия повторного использования
не подтверждены в автоматическом режиме. Пользователь получает актуальный файл
вручную с официального портала, проверяет условия использования и указывает URL
именно того набора, откуда получен файл. Сторонние зеркала не являются основанием
для автоматического утверждения актуальности сведений.

## Принцип безопасности

```text
Официальный JSON → validate → stage (закрытая таблица)
                                ↓
                    сверка каждой записи с текущим
                    официальным сайтом суда
                                ↓
                         approve (явно)
                                ↓
                     courts.status=verified
                                ↓
                   публичная страница + поиск
```

- `validate` проверяет файл **без подключения к БД**.
- `stage` создаёт batch и кандидатов, но возвращает `published: 0`.
- `approve` принимает **одну** запись с идентификатором, проверенной
  ссылкой, датой и ответственным проверяющим; требует оба флага подтверждения.
- Повторная загрузка одинакового файла идемпотентна по SHA-256.
- История изменений существующего суда сохраняется в `change_events`.
- Не формируются судьи, назначения, подсудность и сведения о председателях:
  для них нужны отдельные проверенные источники.

## Локальный запуск (Docker Desktop)

1. Обновите исходный код ветки `feat/001-court-portal-foundation`.
2. Запустите PostgreSQL и остальные сервисы через `scripts/start-local.ps1`.
3. Если база уже существовала, примените новую миграцию:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\apply-import-migration.ps1
```

4. Скачайте **самостоятельно** официальный JSON-набор контактов и сохраните
   его как `data/import/moscow-contacts.json` в папке проекта.
5. В PowerShell из папки с `compose.local.yaml`:

```powershell
docker compose -f compose.local.yaml run --rm importer validate /input/moscow-contacts.json
```

6. После проверки условий использования и точного URL набора:

```powershell
docker compose -f compose.local.yaml run --rm importer stage /input/moscow-contacts.json --source-url https://data.mos-gorsud.ru/opendata
```

В приведённой команде `--source-url` указан **адрес каталога как пример формата**:
для фактической загрузки замените его на проверенную страницу конкретного набора
на домене `data.mos-gorsud.ru`. Не используйте каталог как точную
ссылку на файл, если он не является местом публикации этого набора.

Результат: JSON с `batch_id`, `records` и `published:0`.
После этого все записи по-прежнему скрыты.

## Ручная публикация одной проверенной записи

Сначала сверьте её с актуальной страницей суда и проверьте условия
использования набора. Укажите фактическую дату проверки. Пример формы команды:

```powershell
docker compose -f compose.local.yaml run --rm importer approve --batch <BATCH_ID> --code <КОД_СУДА> --reviewer <ИМЯ_ПРОВЕРЯЮЩЕГО> --checked-on <ГГГГ-ММ-ДД> --verification-url <АКТУАЛЬНАЯ_ОФИЦИАЛЬНАЯ_ССЫЛКА> --attest-current --attest-reuse-rights
```

Параметр `--verification-url` должен вести непосредственно на официальный сайт
того же суда, что указан в импортируемой записи. При несовпадении или отсутствии
свежей проверки утверждение будет отклонено.

Не запускайте `approve` для демонстрационных и исторических данных.

## Что пока не реализовано

- Прямое и периодическое скачивание актуального набора по проверенному endpoint.
- Проверка условий использования программой (требует юридической верификации).
- Полноценный веб-интерфейс редакторского согласования.
- Автоматическое сопоставление реорганизаций, судей и участков мировых судей.
- Сквозные DB-интеграционные проверки approve (планируется).

## Ограничения формата

Импортёр принимает JSON-массив, либо объект с массивом `data` или `records`
(до 5 МБ, до 5000 записей). Любая неизвестная структура или конфликт
идентификаторов приводит к отказу без частичной публикации. Если текущий
официальный экспорт имеет другой формат, сначала необходимо проверить его
документированную схему и адаптировать парсер с тестами.
