Редакционная партия от 1 ноября 2026 г. Ветка `infra/coolify-russian-vps`.

## Покрытие на данный момент

- **27 судов** — локальные подборки опубликованных официальных списков (20 прежних + 3 Басманный/Лефортовский/Пресненский + 4 новых).

- **5 судов** — только ФИО председателя с официальной карточки суда (Замоскворецкий, Кузьминский, Мещанский, Хамовнический, Щербинский).
- **391 персональная запись** в каталоге, что не равно численности действующих судей. Добавлены 51 ФИО из четырёх опубликованных официальных списков и пять руководителей с маркировкой источника.
- **21 дело** связывается с конкретным судьёй и официальным реестром; в **18** указан результат, в **3** исход не подтверждён. Это **не полный массив** и не рейтинг.
- **0 полностью прочитанных, независимо проверенных мотивировочных текстов в персональном модуле**. Публикуемые персональные правовые позиции на этом этапе отсутствуют.

## Технический путь от дела к судебной позиции

1. Получить из официального списка точное сочетание **суд + номер/УИД + судья + вид судопроизводства + результат**.
2. Найти на официальной карточке дела опубликованный полный текст. Для отметки «публикация запрещена» не извлекать и не публиковать документ.
3. Проверить дату, автора акта, статус, ограничения на публикацию по Федеральному закону № 262-ФЗ, обезличивание и права на повторное использование. Семейно-правовые решения в локальный полнотекстовый архив не включать.
4. Прочитать решение и указать **реально применённые нормы**, выводы суда и аргументацию. Разделить цитату/норму/редакторское резюме. Проверить, был ли акт обжалован и что произошло в вышестоящей инстанции, только при наличии самостоятельного официального источника.
5. Сохранить SHA-256 полученного первоисточника, дату сверки, отдельные юридические цитаты и статус ограничений.
6. Передать сведения в `importer/promote_moscow_judge_reasoning.py` с локальным оригиналом PDF/TXT, предварительно заполненным JSON и `editorialVerified: true`. Команда `--check` проверяет точную привязку к судье, номеру, официальному домену, наличию исходного файла, его SHA-256 и полноте статусов. `--append` применяется только после приёмки:

```bash
python importer/promote_moscow_judge_reasoning.py --staged /path/to/reviewed-decision.json --check
python importer/promote_moscow_judge_reasoning.py --staged /path/to/reviewed-decision.json --append
```

Редакционно утверждённые результаты сохраняются в `apps/web/app/data/moscow-judge-reviewed-decisions.json`. Пока массив пуст. Персональная страница судьи уже умеет отображать проверенные **нормы закона и мотивировочную позицию** для соответствующего дела после прохождения всех обязательных фильтров. Полные копии ограниченных актов, данные сторон и неподтверждённые «статистические склонности» судей не публикуются.

**Важно:** SHA и структурные проверки подтверждают наличие проверяемого файла и отсутствие очевидных подмен в базе, но сами по себе не заменяют оценку содержания и действительного назначения судьи.

## Следующие нерешённые вопросы

- Полные опубликованные судейские списки пяти оставшихся районных судов, динамика кадровых назначений.
- Подключение машиночитаемых наборов https://data.mos-gorsud.ru/ после проверки состава полей, лицензии, ограничений и актуальности.
- Реальное скачивание и чтение официальных мотивировочных актов, проверка конкретных норм права, сопоставление апелляционных результатов и создание полного юридического резюме.
- Браузерная проверка после самостоятельного деплоя в Coolify; новые страницы судей по-прежнему закрыты от индексации.

## Релиз

Не включать массовый SEO для персональных страниц до подтверждения полноты. Последний коммит должен пройти все GitHub Actions (`build`, `importer-tests`, `windows-safety`, `postgis-geometry-smoke`, `local-host-smoke`). Публикация на VPS не выполняется автоматически этим коммитом.
