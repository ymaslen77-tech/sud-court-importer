# Москва: сквозной поиск по номеру апелляции и безопасный статус прошедших заседаний

**Редакционный этап:** 27.11.2026. **Область изменений:** публичная выдача только уже подтверждённых судебных реестровых метаданных, без нового текста судебных актов и без данных участников.

## Обнаруженный разрыв поиска

При этом он находил московские записи по номеру **первой инстанции**, но не по двум ранее установленным номерам **зарегистрированных апелляционных материалов**. `/courts/moscow/cases` уже показывал их как связанные записи, поэтому источники существовали, но были неполно подключены к единому поиску.

## Исправление

- `moscow-region-case-index.ts` больше не теряет уже проверенные идентификаторы апелляции: берёт их только из `moscowJudgeCaseCrosscheck`, а номер апелляционного **дела** из отдельного датированного `moscowAppealHearingSnapshot`. Если проверяемой записи нет, соответствующее поле остаётся `null`; номер апелляции для Мещанского дела **не придуман**.
- `moscow-region-case-search.ts` содержит единую поисковую нормализацию: русский регистр, `ё/е`, пробелы около дефиса и слэша, а также варианты знака тире. Она ищет по номеру первой инстанции, проверенному номеру дела в апелляции, номеру апелляционного материала, наименованию суда, категории и опубликованному имени судьи.
- И `/search`, и `/courts/moscow-region/cases` используют один и тот же алгоритм, чтобы исключить разный результат на одинаковый запрос.
- В результатах появились отдельно подписанные **«апелляционное дело»** и **«зарегистрированный апелляционный материал»**, дата регистрации и прямая ссылка на официальный апелляционный источник, когда такая запись уже была сверена.
- Результат первой инстанции показывается отдельно, всегда с предупреждением об **отсутствии удостоверенного итога апелляции**.
- Пара записей из области продолжает оставаться архивными указателями, а не утверждёнными полными карточками дел.

## Историческое заседание — не предстоящее

Снимок карточки Мосгорсуда, просмотренной **13.11.2026**, содержал назначение заседания Никулинского дела **на 19.11.2026 в 10:30, зал 570**. На дату этого этапа **27.11.2026** назначенная дата уже прошла. Однако повторно получить первичную страницу для проверки результата не удалось.

Оба пользовательских интерфейса — общий московский индекс и конкретная карточка районного суда — явно маркируют прошедшую дату. Функция `isPastPublishedHearingDate` только сравнивает календарные даты. **Она не делает утверждения** о том, состоялось ли заседание, перенесено ли оно или вынесен ли судебный акт. Просроченный снимок нельзя использовать для планирования посещения.

## Контроль качества

Автотест `apps/web/tests/moscow-appeal-crosssearch.test.cjs` выполняет **реальную функцию сборки поискового индекса** с синтетическими импортами и имеющимися датированными JSON-источниками, проверяя:
- оба реестровых материала и отсутствие номера апелляционного дела там, где он ещё не известен;
- единый поиск по 02-0514/2026, 33-53951/2026, Ж-65034/2026, 02-2880/2026, Ж-64264/2026 и архивному областному номеру 33-32970/2026;
- отсутствие неподтверждённых судебных исходов, текста решения и новых личных данных;
- оба UI для прошедшего заседания, отдельные ссылки на первоисточники, сохранение `noindex`.

Тест подключён к общему CI и московской специализированной проверке. После PR и зелёного CI требуется отдельный **ручной Coolify Deploy**. Успешный предыдущий Deploy не включает последующую ветку автоматически при ручном режиме.
