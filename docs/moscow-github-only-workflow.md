# «Суды России»: разработка GitHub → ручной Deploy

Состояние: 10.11.2026. Рабочая ветка: `infra/coolify-russian-vps`.
Это внутренний регламент разработки, не публичная юридическая справка.

## Принятая схема

1. Помощник готовит и изменяет **код, справочные данные и тесты в GitHub**.
2. GitHub Actions проверяет источники, допустимость публичных JSON,
   качество справочных карточек и сборку Next.js.
3. Спорные поля, непроверенные тексты решений и отсутствие официальных
   данных остаются на проверке; результат тестов не заменяет правовую экспертизу.
4. После успешной проверки владелец вручную нажимает **Deploy**
   приложения `sudy-web` в Coolify. Никаких команд в терминале VPS
   для обычной разработки и публикации не требуется.

**SSH-to-VPS workflow удалён**; конфигурационные скрипты установки
`sudy-stage` удалены из рабочей ветки. Команды не запускаются на
удалённом сервере. Прежде созданный пользователь на VPS не удалялся,
так как это потребовало бы отдельного администрирования сервера.

## Что уже доступно в GitHub

- `apps/web/app/data/moscow-official-dataset-catalog.json`:
  40 описаний официальных наборов (8 первой инстанции, 11 апелляционных,
  5 указателей, 9 справочных и 7 исключённых). Содержит
  идентификаторы, названия, тип, адрес страницы, паспорт и **кандидат**
  адреса для получения JSON. Сами выгрузки отсутствуют.
- `importer/moscow_open_data_registry.py`: программный эталон этих
  40 идентификаторов; каталог в веб-приложении проверяется на точное
  совпадение с ним.
- `apps/web/app/courts/moscow/sources/page.tsx`: внутренний раздел
  первоисточников, доступный из каталога судов Москвы. Исторические
  URL не выдаются за проверенные в реальном времени.
- `apps/web/app/data/moscow-official-minimum-registry.json` и
  `moscow-district-practical-facts.json`: отобранные официальные
  справочные сведения о 35 районных судах города.
- `apps/web/app/lib/official-reference-courts.ts`:
  справочные карточки Московской области (отдельно от города Москвы).
- `apps/web/app/data/moscow-judge-bulk-cases.json`: публичная
  коллекция метаданных массовой загрузки; **в текущем состоянии
  массив пуст**. Нет оснований утверждать, что на сайте опубликованы
  все судебные дела из официальных выгрузок.

## Какие оригиналы НЕ переносились в GitHub

Согласно предыдущему аудиту, на VPS остались два больших файла:

| Официальный набор | Идентификатор |
| --- | --- |
| Гражданские дела первой инстанции | `1577116594824-casesgroupfirstcivilhxvgb` |
| Гражданская апелляция МГС | `1577117744056-casesgroupmgsappealcivilwtxga` |

Эти оригиналы не доступны через GitHub-коннектор. В текущем проходе
их полный объём и SHA-256 не проверялись. Они могут содержать
персональные сведения сторон и документы с ограничениями публикации.
Не копировать их в Git, Git LFS, общедоступные артефакты Actions или
в веб-приложение. Крупные приватные файлы не становятся безопасными
от изменения места хранения.

Официальная точка входа:
https://data.mos-gorsud.ru/opendata

На стороне GitHub **возможны** обработка разрешённых исходных данных
в изолированной среде и создание только обезличенного утверждённого
артефакта, но исключительно после документированной проверки условий
повторного использования, ограничений источника, схемы и правомерности
публикации. Нынешний workflow не скачивает материалы дел и не утверждает
доступность старых URL.

## Проверки в GitHub Actions

`.github/workflows/moscow-github-only-quality.yml` на push в рабочую
ветку, PR и ручном запуске:

- тестирует точное соответствие 40 наборам каталога;
- запрещает коммитить сырые архивы дел и файлы приватного `data/import`;
- проверяет поля публичного JSON на случайное включение участников,
  непроверенной мотивировки, неизвестных URL и дубли;
- запускает существующие тесты официальных контактов и полноты
  справочных досье;
- выполняет `pnpm check` и `pnpm build`.

Права workflow: `contents: read`. Ему не нужны секреты VPS, API-токен
Coolify или база данных. Он ничего не публикует.

## Ваш единственный регулярный шаг

Проверить успешный GitHub Actions для требуемого коммита, затем
запустить **Deploy** в Coolify, если `sudy-web` настроен на эту ветку.
Чтобы Deploy был **только вручную**, автоматический Deploy-on-push
в Coolify должен быть отключён (проверяется в интерфейсе владельцем).
После публикации проверить
`/courts/moscow`, `/courts/moscow/sources`, поиск и SEO.

Отдельная необязательная уборка: если SSH-интеграция больше не нужна,
в GitHub Settings → Environments → `vps-stage` можно удалить пять
старых SSH-секретов; в Actions Variables удалить
`SUDY_VPS_AUTOMATION_ENABLED`. Ни один активный workflow в этой
ветке больше не должен использовать этот набор. Удаление пользователя
с VPS не выполнялось.

## Не считать завершёнными

- Полную приёмку составов судей и актуальных полномочий.
- Полную индексную обработку двух приватных JSON с истинными
  совпадениями УИД, номеров, судов и апелляционных стадий.
- Проверку реальных полных текстов решений, правомерности публикации,
  норм права, исходов апелляций и обезличивания.
- Актуализацию всех адресов, телефонов и сведений по Московской области.

Следующие итерации разработки ведутся GitHub-first без поручений
пользователю запускать консольные команды. Ограничения источника и
правовая проверка обязательны даже при успешных тестах.
