# Подробные карточки судов: сведения, изменения, карты, фото и SEO

## Поля и достоверность

Карточка суда показывает: название и вид, субъект РФ, адрес, отдельные телефоны, email, проверенную дату контактов, режим работы/приём, ссылки на правила подачи и подсудность, подтверждённый состав судей, расположение и историю изменений. Неизвестные значения остаются пустыми с явным пояснением.

Ключевые принципы:
- Нельзя автоматически переносить руководителя сайта суда в действующего председателя без свежей проверки назначения.
- Часы работы и часы личного приёма судьи не равнозначны. Разные телефоны экспедиции, приёмной и канцелярии должны иметь разные метки.
- Судебные участки и судебные присутствия не автоматически самостоятельные судебные органы.
- Списки судей, должностей, даты указов и номера кабинетов проверяются отдельно; источники могут обновляться не одновременно.
- Факты, подтверждённые недавно, сохраняются вместе с источником и датой. Изменившаяся HTML-страница сама по себе НЕ доказывает изменение телефона, ФИО или должности.

## Техническая модель

- `db/migrations/005_court_profiles_monitoring.sql`: приватная очередь `court_profile_candidates`, опубликованные `court_profile_fields`, лицензированные `court_facade_media`, источники для мониторинга `court_source_watch`, изменения страниц `court_source_watch_events`.
- `importer/profile.py propose`: создаёт необнародованное предложение одного поля только по официальному HTTPS источнику.
- `importer/profile.py approve`: отдельное подтверждение ревьюером актуальности и прав на использование; атомарно меняет одно поле в `courts` либо `court_profile_fields`, сохраняет `change_events` и источник.
- Координаты принимаются как WGS84 JSON с latitude и longitude только после ручной проверки; геокодирование по текстовому адресу не производит автоматической публикации.
- Судьи выводятся только из `judicial_appointments` с проверенным источником и актуальным периодом; карточки имён не генерируются из случайных текстов.

## Монитор изменений официальных страниц

CLI `importer/watch.py register`: обязательны court ID уже проверенного суда, официальная HTTPS ссылка, scope из contacts/judges/hours/documents/general, именная фиксация ответственного, подтверждение условий источника. До регистрации необходимо отдельно проверить право автоматического запроса.

CLI `importer/watch.py check`: выбирает due источники, проверяет robots.txt (ошибка трактуется как запрет), делает условный HTTP запрос с ETag/Last-Modified, ограничивает объём ответа 1 МиБ, отклоняет redirects на другие домены и HTML hash differences записывает в приватную очередь `court_source_watch_events`. Предложения по отдельным контактам/судьям не утверждаются автоматически.

Опциональный worker `court-watch` в Docker Compose, профиль `watch`: раз в сутки запускает до 5 проверок из зарегистрированной очереди; интервалы individual watches от 24 до 720 часов. Если Docker Desktop выключен, проверки не работают. Это **не гарантия актуальности** и не сервис скрытого обхода ограничений.

Пример из каталога проекта (после того, как реальные источники и право мониторинга подтверждены):

    docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/watch.py register --court-id <ID> --url https://mos-gorsud.ru/rs/lefortovskij/help/hours --scope contacts --reviewer <REVIEWER> --cadence-hours 48 --attest-permission
    docker compose -f compose.local.yaml --profile watch up -d court-watch
    docker compose -f compose.local.yaml logs -f court-watch

### Обработка обнаруженных изменений

После периодического запуска можно посмотреть очередь изменений:

    docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/watch.py pending --limit 50

По официальному первоисточнику проверьте конкретные поля и назначения. При необходимости внесите отдельное предложение через profile.py propose или judges.py nominate, затем утвердите его независимо. Только после обработки изменения пометьте событие как проверенное:

    docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/watch.py review --event-id 1 --reviewer "Имя редактора" --attest-reviewed

Если HTML поменялся несущественно, допустим --ignore с аудиторским следом. В базе хранятся reviewed_by и reviewed_at. Проверки не являются гарантией непрерывной доступности сайтов или круглосуточной свежести данных.

## Карты и фотографии

- Карта отображается только при подтверждённых координатах. Встраивание OpenStreetMap выполняется лишь после клика пользователя; с открытой атрибуцией © OSM contributors/ODbL, ссылкой на карты и официальным источником координат. Для массовой нагрузки нужен лицензированный tile provider или собственные тайлы: https://operations.osmfoundation.org/policies/tiles/.
- Фото фасадов загружаются ТОЛЬКО из проверенного файла на собственном сервере `/court-media/...` с разрешением правообладателя или совместимой лицензией и именем автора, ссылкой на источник и условия использования. Google Maps/панорамы и непроверенные фото из интернета не копируются.
- Если координат или фото нет, показывается честное состояние «требуется проверка». Никаких рисованных официальных гербов, печатей или сгенерированных фасадов как реальные.

## Загрузка лицензированных фотографий фасада

Сначала вручную получите разрешённую к повторной публикации реальную фотографию здания с отдельным подтверждением того, что на ней именно требуемый суд. Проверьте автора и условия конкретной лицензии. Не скачивайте фото или панорамы коммерческих карт без разрешения правообладателя.

Положите файл JPEG/PNG/WebP в `data/import/facade.jpg` (не добавлять в Git). После того как конкретный суд прошёл редакционную проверку и имеет `court_id`, используйте:

    docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/photo.py --court-id 1 --file /input/facade.jpg --source-url https://commons.wikimedia.org/wiki/File:CONFIRMED_FILENAME --license-url https://creativecommons.org/licenses/by-sa/4.0/ --license-name "CC BY-SA 4.0" --author "Реальный автор" --reviewer "Имя проверяющего" --attest-rights --attest-facade-identity

Пример с `CONFIRMED_FILENAME` и ID 1 — шаблон, **не ссылка на существующую лицензию конкретного фасада**. Отсутствие реально лицензированного файла означает отсутствие фото на сайте.

Обработчик проверяет границы 10 МиБ/15 Мп, снимает EXIF, конвертирует изображение в локальный WebP `/court-media/`, записывает правообладателя и лицензию в `court_facade_media`. Фото сохраняется в `apps/web/public/court-media`, для его появления в работающем Docker-web контейнере требуется пересборка:

    docker compose -f compose.local.yaml up --build -d web

Фото исходно НЕ автоматически загружаются с сайта суда, Wikimedia Commons или поисковиков. Их использование требует установленной конкретной лицензии.

## SEO и индексирование

- URL карточки `/courts/{region}/{court}` постоянный; канонический адрес, уникальные title/H1/description, Breadcrumbs, ссылки на профильный тип суда и официальный источник.
- JSON-LD `schema.org/Courthouse` с реальным адресом, телефоном и геоточкой **только при подтверждённых полях**. Не обещать расширенные результаты поисковиков.
- Noindex если адрес/официальная ссылка/источник не подтверждены либо базовая верификация старше 180 дней; это порог для SEO качества, а не юридическое заявление о достоверности других полей.
- `/sitemap.xml` содержит только соответствующие проверенные карточки из API. Сейчас ограничение 5000 URL карточек на один sitemap. Для масштабирования потребуется индекс и шардинг sitemaps.
- Не создавать тонкие географические/тематические URL без уникальной проверенной информации. Допустимые дополнительные страницы после подтверждения: состав суда, подсудность, порядок приёма, реквизиты, новости суда, опубликованная практика с номером дела и судебной инстанцией, архив предыдущих должностей.

## Пилот Лефортовского суда

В `importer/seeds/lefortovsky-sourced-pilot-unapproved.json` сохранены сведения с официального `mos-gorsud.ru`: адрес, различные контакты, часы работы, председатель и указанный на официальной странице состав судей. Дата последнего обновления страницы судей — 22.04.2026; на момент создания пилота нет независимого свежего подтверждения каждого назначения.

Пилот **не опубликован автоматически**: не подтверждены точная геоточкой, фото с правами, обновления персонального состава и индивидуальный редакционный допуск. Следующий шаг — пройти ручную проверку источников/повторное подтверждение разрешений, затем stage → approve.

## Оставшиеся ограничения

Монитор пока не извлекает автоматически ФИО и номера телефонов из меняющейся HTML-разметки; нужны проверенные адаптеры форматов по провайдерам, unit+integration tests и очередь редакторов. Нельзя использовать простой diff HTML как автоматическое доказательство кадрового назначения. Для круглосуточной проверки нужен постоянно работающий хост.
