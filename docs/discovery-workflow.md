# Общероссийский каталог: обнаружение → проверка → публикация

## Зачем второй уровень данных

Официальные каталоги не предоставляют одинаковый набор полей для каждого суда.
В частности, [реестр арбитражных судов](https://arbitr.ru/?id_doc=20563&id_sec=353)
содержит наименования судов субъектов РФ и отдельных судебных присутствий,
но **не даёт в том же списке надёжного классификационного кода и адреса каждому объекту**.

Нельзя генерировать коды типа 77AS0001, подставлять адрес из названия
региона или объявлять присутствие самостоятельным судом.

Теперь предусмотрены два независимых уровня:

1. **Discovery:** название, тип, URL официального перечня; официальный
   URL суда, регион и код добавляются лишь при наличии доказательств.
   Данные в court_discovery_batches и court_discovery_rows; публичный API
   их не возвращает.
2. **Verified court:** проверенные контактные сведения и идентификаторы,
   подтверждение редактором и история изменений. Только эта таблица
   отображается в обычном каталоге /courts.

## Первый список из арбитражного реестра

Файл: importer/seeds/arbitration-subjects-official-list-unreviewed.json

- 87 записей с наименованиями арбитражных судов субъектов;
- 2 отдельно отмеченных постоянных судебных присутствия;
- 89 строк; это НЕ счётчик действующих судов всей арбитражной системы;
- список составлен по опубликованному официальному перечню arbitr.ru;
- адресов, телефонов, кодов и выдуманного деления округов нет;
- веб-страница /courts/arbitration показывает лишь исходные названия
  и ссылку на источник, подчёркивает необходимость сверки и имеет noindex.

Существующий список 10 новосибирских федеральных судов остаётся
отдельной, также неутверждённой выборкой. Эти 10 плюс 89 — 99 строк
исходных файлов, а не 99 опубликованных судов.

## Проверка на локальном хосте (Docker Desktop)

Для существующей базы сначала:

    powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\apply-import-migration.ps1

Будут применены миграции 002 и 003 (идемпотентные).

Скопируйте снимок в папку, доступную контейнеру:

    New-Item -ItemType Directory -Force data\import | Out-Null
    Copy-Item importer\seeds\arbitration-subjects-official-list-unreviewed.json data\import\arbitration.json

Выполните:

    docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/discovery.py validate /input/arbitration.json
    docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/discovery.py stage /input/arbitration.json --captured-on 2026-10-12
    docker compose -f compose.local.yaml run --rm --entrypoint python importer /work/importer/discovery.py stats

Для следующих загрузок --captured-on ставится по фактической дате
получения и проверки исходного перечня. Она не означает юридическую
верификацию контактов или полномочий судов.

stage не пишет в таблицу courts и не публикует карточки.
Повторное добавление того же файла идемпотентно по SHA-256.
stats считает строки исторических снимков (они могут пересекаться),
поэтому не является счётчиком уникальных действующих судов.

## Формат для других официальных списков

Пример JSON-массива:

    [
      {
        "registry": "arbitr-courts",
        "courtKind": "arbitration-subject",
        "courtName": "Арбитражный суд Республики Алтай",
        "sourceRecordUrl": "https://arbitr.ru/?id_doc=20563&id_sec=353"
      }
    ]

- Один файл — один реестр и один точный URL первичного перечня.
- Дополнительные поля regionCode/regionName (вместе), courtCode,
  courtSiteUrl, courtAddress только при реальных подтверждениях.
- Для мировых судей magistrate-area означает участок, не личность судьи.
- Нельзя считать надёжными вымышленные коды арбитражных судов.
- Разрешённость массового доступа/повторного использования источника
  должна быть отдельно установлена до включения автоматической загрузки.

## Следующий обязательный этап

- Подтверждение полного перечня по всем категориям и регионам.
- Разделение суда, судебного участка, судебного присутствия и округа.
- Кабинет верификации источников и сопоставления идентификаторов.
- Отдельная сверка адресов, телефонов, судей, подсудности и практики.
- Контроль полноты по реестрам, а не произвольным ожидаемым числам.
