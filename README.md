# Суды России — единый правовой портал

Фундамент независимого справочно-информационного портала судов РФ. Текущая версия не публикует вымышленные сведения. Реализованы закрытые очереди официальных исходных выборок, проверка источников, контроль изменений и ручное утверждение каждой карточки. Эти выборки не равнозначны опубликованному проверенному реестру.

## Локальный хост на Windows (рекомендуется)

Для запуска нужен работающий **Docker Desktop**. Git необязателен: проект можно получить ZIP-архивом. Node.js и pnpm отдельно устанавливать не требуется.

**Если Git установлен:**

```powershell
git clone --branch feat/001-court-portal-foundation https://github.com/ymaslen77-tech/sud-court-importer.git
cd sud-court-importer
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-local.ps1
```

**Если Git не установлен:** скачайте [ZIP рабочей ветки](https://github.com/ymaslen77-tech/sud-court-importer/archive/refs/heads/feat/001-court-portal-foundation.zip), распакуйте архив, перейдите в папку с `compose.local.yaml` и выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-local.ps1
```

Чтобы увидеть новые изменения без Git, скачайте свежий ZIP и замените код проекта. Docker-том с БД сохраняется при обычной пересборке.

Скрипт поднимет базу данных, API и Next.js в изолированной Docker Compose-среде, дождётся HTTP-ответа и **откроет сайт в браузере Windows**.

- **Сайт:** http://localhost:4173
- **Health API:** http://localhost:4174/api/v1/health
- **Каталог Москвы:** http://localhost:4173/courts/moscow

Порты опубликованы **только на 127.0.0.1**, сайт недоступен из внешнего интернета. PostgreSQL вообще не открывает порт на компьютере. Отдельное имя сети и отдельный том для БД позволяют не смешивать проект с другими Docker Compose-проектами.

### Управление

```powershell
# Проверить состояние:
docker compose -f compose.local.yaml ps

# Посмотреть сообщения сервисов:
docker compose -f compose.local.yaml logs --tail 100

# Остановить сервисы (данные БД останутся):
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\stop-local.ps1

# Пересобрать после изменений:
docker compose -f compose.local.yaml up --build --detach
```

В случае конфликта порта 4173 необходимо изменить внешний порт в `compose.local.yaml` и URL в `scripts/start-local.ps1` одновременно.

## Стек и структура

- Next.js / React / TypeScript — публичные серверные страницы и SEO.
- NestJS / TypeScript — HTTP API.
- PostgreSQL + PostGIS — проверенные записи, назначения и геоданные.
- Docker Compose — выделенный локальный хост.
- Python importer: валидация JSON, закрытый staging, ручное утверждение судов. Автоматическая выгрузка с официального сайта пока не реализована.
- Полнотекстовый поиск и личный кабинет — будущие задачи.

## Навигация и дизайн

- `/` — главная страница, фирменный стиль, поиск и маршруты.
- `/courts` — каталог опубликованных судов и регионов.
- `/courts/moscow` — пилотный регион (без подставных данных).
- `/search?q=...` — поиск по подтверждённым названиям судов.
- `/judges`, `/laws`, `/practice`, `/guides`, `/jurisdiction`, `/services` — структурированные страницы направлений в разработке.
- `/sources` — политика источников и проверяемости.

Большинство ещё не наполненных разделов закрыто для индексации через `noindex`; пустые карточки не выдаются за реальные.

Детальный стандарт интерфейса: [docs/interface.md](docs/interface.md).

## API

- `GET /api/v1/health`
- `GET /api/v1/regions`
- `GET /api/v1/courts/search?q=название`
- `GET /api/v1/regions/:region/courts`
- `GET /api/v1/regions/:region/courts/:court`

Доступны только записи `verified`. Без предварительной загрузки и проверки официальных сведений каталог остаётся пустым — это ожидаемое состояние. Файлы `db/migrations` выполняются при **первой инициализации** пустого тома PostgreSQL.

## Синхронизация официальных контактов московских судов

Реестр `data.mos-gorsud.ru` действительно содержит тему «Контакты и часы приёма». Добавлен **офлайн-адаптер** `importer/moscow_sync.py` для нормализованного JSON с идентификаторами судов. Команда `validate` проверяет файл, команда `sync` проверяет точную ссылку на официальный набор, дату получения и разрешение на повторное использование, добавляет записи в staging и ставит изменённые контакты в очередь редакционной проверки. Идемпотентность и отсутствие автоматической публикации проверяются в CI. Дополнительно предусмотрен **отключённый по умолчанию** Docker-профиль `intake`: локальный каталог `data/import/inbox` проверяется каждые 6 часов, если пользователь сам запустит `docker compose -f compose.local.yaml --profile intake up -d court-intake`. Он не скачивает сайты и требует отдельно подготовленный манифест с подтверждением источника и прав.

**Автоматического скачивания с data.mos-gorsud.ru пока нет:** конкретная схема набора и условия машинного доступа требуют проверки. Подробнее: [docs/moscow-contact-sync.md](docs/moscow-contact-sync.md).
## Общероссийский импорт: региональные снимки и контроль изменений

- **Добавлен адаптер реальной выдачи ГАС «Правосудие»**: `importer/sudrf_listing.py` проверяет сохранённую региональную HTML/текстовую страницу, распознаёт подтверждённые официальным источником типы `RS`, `OS`, `GV`, `KV`, `AJ`, валидирует контакты, код и домен.
- Команда `sync` выполняет безопасный нормализованный staging и записывает SHA-256 исходной страницы, дату получения, подтверждение условий использования и имя ответственного. Повторный идентичный снимок не создаёт публичных карточек.
- **Сравнение с предыдущим снимком:** `importer/registry_diff.py` находит новые коды и изменившиеся контакты/адреса. Отсутствующие суда в неполных снимках **не считаются закрытыми**. Diff items требуют проверки редактора.
- `db/migrations/007_court_registry_diffs.sql` хранит историю сравнения и статус проверки каждого изменения; существующие тома БД обновляются `scripts/apply-import-migration.ps1`.
- `importer/coverage.py` — read-only отчёт по субъектам, числу реально проверенных судов, очередям изменений и здоровью фонового мониторинга.
- Реальный пример официального списка Новосибирской области и тесты: `importer/tests/fixtures/official_sudrf_novosibirsk_excerpt.txt`. **4 записи в учебном фрагменте, не вся область**.

Пошаговый процесс и ограничения источников: **[docs/sudrf-regional-sync.md](docs/sudrf-regional-sync.md)**. Без разрешённого регулярного канала получения актуальных файлов система пока автоматически обрабатывает новые снимки **после их поступления**, но не обещает непрерывный сбор по всем регионам.
## Ссылки на судебные дела с официального портала

Новый `importer/cases.py` и миграция `008_official_case_references.sql` создают две независимые стадии: закрытая заявка с УИД и официальным URL, затем ручное подтверждение. УИД должен содержать внешний код заранее проверенного суда. На карточке выводятся только утверждённые ссылки, без копирования ФИО участников или ошибочной привязки судьи по инициалам. Эталон: [docs/official-case-links.md](docs/official-case-links.md).
## Безопасное локальное обновление и приёмка

Перед обновлением Windows 11 запускайте `pwsh -NoProfile -File .\scripts\safe-update-local.ps1` из **обновлённой рабочей ветки**. Скрипт сначала создаёт проверяемый custom PostgreSQL dump и резервную копию старого кода, затем обновляет исходники, миграции и health checks. Не использует `docker down -v`. Копия находится в `$HOME\sud-court-backups`. Восстановление не автоматическое и должно проводиться администратором отдельно.

План поэтапной приёмки и реальные ограничения: [docs/acceptance-roadmap.md](docs/acceptance-roadmap.md).

**Реальный пилот Лефортовского районного суда** — [доказательства и инструкции](docs/lefortovsky-official-pilot.md). Добавлен импорт `mos-gorsud-court` для индивидуальной официальной страницы с кодом `77RS0014` из официального УИД. Пилот пока в исходном JSON с пометкой `unreviewed`; публикации в пользовательскую БД не выполнялось.
## Подробные карточки и мониторинг актуальности

- Для подтверждённых судов расширена карточка: контакты, судебная категория, часы работы и приёма, ссылки на подачу документов/подсудность, судьи и назначения, журнал изменений.
- Карта OpenStreetMap загружается по клику **только при подтверждённых координатах**; фото фасада выводится только при сохранённой лицензии, авторе и локальном файле.
- Появился двуступенчатый editorial workflow: `importer/profile.py propose/approve` для поля суда, `importer/judges.py nominate/approve/close` для судейских назначений.
- Монитор `importer/watch.py register/check`: разрешённые URL официальных источников, уважение robots.txt, ETag/Last-Modified, SHA-256 изменений, приватная очередь на проверку; никаких автоматических кадровых «правок» по HTML.
- Опциональный Docker worker `court-watch` проверяет зарегистрированные сайты примерно ежедневно, **только** после подтверждения допустимости доступа. Пока локальный компьютер/контейнер выключен, проверки не выполняются.
- Миграции `005_court_profiles_monitoring.sql` и `006_judge_appointment_review.sql` входят в `scripts/apply-import-migration.ps1`.
- SEO: проверенный структурированный тип `Courthouse`, canonical, `/sitemap.xml` только для качественных записей, индивидуальный `noindex` при устаревании или отсутствии источника.

Первое подготовленное досье на основании официальных страниц Лефортовского суда — `importer/seeds/lefortovsky-sourced-pilot-unapproved.json`. Оно **не опубликовано автоматически**, а требует ручной проверки дат, назначений, прав на использование и достоверности отдельных полей.

Подробнее: **[подробные карточки и мониторинг](docs/court-cards-and-monitoring.md)** и **[проверка назначений судей](docs/judicial-appointments-monitoring.md)**.

## Проверка кадровых данных и готовности к запуску

- `importer/roster.py`: источник, 11 наблюдений списка судей Лефортовского районного суда, реквизиты опубликованных указов и дата обновления страницы. `stage` сохраняет только закрытые сведения, **не** подтверждает действующие назначения. Документация: [docs/judge-roster-intake.md](docs/judge-roster-intake.md).
- `importer/readiness.py`: строго проверяет техническую готовность пилотного запуска по реальным подтверждённым судам, давности сведений, работающему мониторингу и очередям редакционной проверки. Полноту всей России он **не** подтверждает.
- Новый [безопасный сценарий обновления Windows](docs/localhost-safe-update.md): `scripts/update-local-safe.ps1`, резервное копирование `pg_dump` **до** миграций, без удаления Docker-томов.

## Судебная система: виды судов и категории судей

- `/courts/types` — **15 категорий** в 4 группах: высшие судебные органы, общая юрисдикция, военные и арбитражные суды.
- `/courts/types/:kind` — страница категории с официальной ссылкой, описанием инстанции и списком **только проверенных** судов; при пустом списке установлено `noindex`.
- `/judges` — навигация по категориям судей, включая мировых, районных, областных, военных, апелляционных и кассационных. Персональные ФИО пока не публикуются.
- Новая миграция `db/migrations/004_court_categories.sql` добавляет строгое поле `court_kind` с безопасным значением `unclassified`. Данные импортёра классифицируются только при подтверждённом официальном коде; неуверенные записи не получают выдуманный тип.
- API `GET /api/v1/courts/categories/:kind` показывает только подтверждённые карточки нужного вида.

Нормативная классификация и ограничения: **[docs/courts-and-judges-taxonomy.md](docs/courts-and-judges-taxonomy.md)**. Вдохновение UX — Sudact, но источники сведений и данные сохраняются собственные/официальные.

Для существующей базы выполните `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\apply-import-migration.ps1` после скачивания обновлённого проекта.

## Общероссийский судебный реестр

Поддержаны три самостоятельные схемы официальных источников: `sudrf-federal` (федеральные суды), `sudrf-magistrate` (судебные участки мировых судей) и `arbitr-courts` (арбитражные суды). Для каждой записи проверяются код суда, соответствие региону, официальный домен, адрес, тип суда и URL первоначальной публикации.

В каталоге `importer/seeds/novosibirsk-federal-official-unreviewed.json` уже подготовлены первые **10 реальных записей** из официального поиска ГАС «Правосудие» по Новосибирской области. Они являются **непроверенной очередью**, не опубликованы в базе и не должны автоматически считаться актуальными. Импортёр умеет положить их в staging; публичными они станут лишь после независимого подтверждения.

Пошаговое расширение на все регионы, формат файлов и матрица полноты сведений: **[docs/nationwide-courts.md](docs/nationwide-courts.md)**.

- [Арбитражные суды России](/courts/arbitration): 87 наименований судов субъектов, 2 присутствия, 21 апелляционный, 10 окружных судов и Суд по интеллектуальным правам из официального перечня arbitr.ru; поиск по названию, пометка «нужна проверка», noindex.
- [Судебные участки мировых судей — Хабаровский край](/courts/magistrates): 75 участков с официальными классификационными кодами 27MS0001–27MS0075. Это **участки**, а не имена судей, noindex.
- 10 кодированных федеральных судов Новосибирской области продолжают оставаться в закрытом импортном снимке, до индивидуальной проверки.

Итого: **206 строк исходных выборок** по разным категориям (121 арбитражный объект + 75 участков + 10 федеральных судов), **не 206 проверенных судов**. Отдельно подготовлены 11 ФИО из официальной страницы судей Лефортовского суда; это закрытые кадровые наблюдения, а не подтверждённые действующие назначения. Полные адреса/контакты/назначения не опубликованы автоматически. Подробнее: [обнаружение, staging и проверка](docs/discovery-workflow.md).

Для существующего Docker тома добавлена миграция 003; выполните `scripts/apply-import-migration.ps1` после обновления исходного кода. Локальный сайт не обновляется автоматически после изменений в GitHub.

## Импорт московских судов

Для источника «Контакты и часы приёма граждан» реализованы строгий парсер, безопасное сохранение кандидатов, проверка дубликатов и отдельное подтверждение перед публикацией. **Никакие записи не публикуются автоматически**, поэтому пока каталог остаётся пустым.

Пошаговая инструкция: **[импорт и утверждение московских судов](docs/moscow-import.md)**. На существующей базе сначала применяется миграция `scripts/apply-import-migration.ps1`.
